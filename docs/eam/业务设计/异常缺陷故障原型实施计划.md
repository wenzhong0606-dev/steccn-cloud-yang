# 异常、缺陷、故障原型实施计划

采用 executing-plans 技能逐项实施。设计依据：[业务流程基线](维护业务对象流程与关闭规则基线.md)、[页面与验收矩阵](维护业务页面模型候选数据与验收矩阵.md)。

目标：形成独立异常发现、缺陷、故障列表和详情操作，所有业务读写经过JS JSON异步模拟接口。技术：独立HTML、公共CSS、原生JS、Node测试。保持旧调用方及旧工单，不让旧验收关闭新问题。

- [x] 写规则测试，验证重复发现保留、分诊多问题、权限、版本冲突、独立验证、恢复时间和缺证拒绝；先观察失败。
- [x] 创建mock/problem-data.js和problem-api.js；独立会话键，原子提交、幂等、审计；不推断旧报告已经独立验证。
- [x] 创建abnormal-events.html、failure-events.html，重做defect-list.html；共享列表控制器和详情表单交互，HTML独立布局；更新导航。
- [x] 更新逐页登记、候选字段接口、目录与进度；实现场景和未实现工单迁移分开记录。
- [x] 运行规则和文档检查，评审PC与移动端；检查失败保留输入、并发刷新、空筛选、长文本、跨页关联五类边界。

本批不实现正式服务、EHS流程、维修逐项验收或保养策略页面。缺陷/故障处置可登记证据后独立验证；旧工单只作为历史引用，不能用新问题ID派旧流程。

交付与限制见[本批验收](../页面设计/维护业务原型/异常缺陷故障原型交付与验收.md)。
