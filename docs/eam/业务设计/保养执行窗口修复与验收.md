# 保养执行窗口修复与验收

日期：2026-10-12。范围：HTML/JSON模拟接口与业务规则，不代表生产后端或真实外部服务验收。

## 最终规则

- 业务日期早于 windowStart：开工和恢复都必须有有效的外部提前授权。没有授权，安全检查返回未通过，直接调用命令也拒绝且不写状态。
- 窗口内：正常安全确认开工，不要求提前授权。
- 超过 windowEnd：允许补做，但 start/resume 必须提供 overdueReason，安全许可与资格不能豁免。
- 授权绑定任务、执行版本、主责/协作快照及执行窗口；改派、退回新版本或授权过期不能沿用原授权。原因、证据、有效日期必填，授权截止须早于原窗口开始。
- 待批/服务失败/驳回/撤回不授权。终态重复回执幂等，旧实例、错误申请版本拒绝。外部决定来源与EAM消费人分开记录。

## 页面与接口

保养任务详情复用统一弹窗组件新增“申请提前开工”“获取提前开工审批结果”；摘要显示实例、日期、有效性。工作台通过任务接口聚合待批入口，消费后自动移除。

所有业务数据依旧在JS预定义JSON及模拟会话存储中，通过异步 EamMaintenanceApi.request 读取/写入。读取外部结果使用 GET /maintenance/tasks/{id}/early-start-result，消费使用 POST /apply-early-start-result，申请使用 POST /request-early-start。sample仅为原型回执选择参数，正式接入必须由服务端校验外部来源和签名，不能接受客户端自行宣告通过。

候选表字段、请求响应与角色已同步[页面登记](../页面设计/页面记录/页面登记.json)及[详情记录](../页面设计/页面记录/保养任务详情-页面数据与接口记录.md)，最终表与API仍待全部模型完成后统一设计。

业务日期沿用配置asOfDate（原型固定2026-10-11）；工厂时区Asia/Shanghai。测试使用可注入businessDate明确验证窗口内外，不修改原型样本日期掩盖漏洞。生产应以服务端工厂业务日为准。
