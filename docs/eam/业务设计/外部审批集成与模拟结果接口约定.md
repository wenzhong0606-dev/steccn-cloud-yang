# 外部审批集成与模拟结果接口约定

日期：2026-10-11。依据：用户明确由外部审批服务负责申请/审批流程，本项目当前通过模拟接口获取审批结果。

## 系统边界

EAM 不建设独立审批服务、流程引擎、审批节点配置或审批任务分配。外部服务负责审批人、节点流转、会签、加签及审批决定；EAM 负责业务申请数据、外部审批引用、结果展示和结果生效后的业务状态及执行入口。

当前阶段遵循已有原型规则：审批样本在独立 JS 中预定义为 JSON，由异步模拟接口读取。模拟接口只是外部服务的替身，不代表真实外部审批服务已接通。维修和保养终止流程已接入外部回执模拟：维修不再直接终止，保养终止决定不再使用客户端 decision 字段。技术验收、问题验证、安全复查及工单草稿专业审核属于现有业务校验，并非审批节点引擎。

## 业务处理原则

提交前检查人员和设备范围、业务状态、申请完整性及逐问题责任安排，保存申请时的业务版本和快照，再关联外部实例。待审批期间，仅冻结与申请冲突的业务动作；不得把“审批中”等同于已终止。

待审批、通过、驳回、撤回、服务失败使用预定义结果样本演示。通过后，EAM 重新校验当前业务版本、未结问题、责任人与期限、控制有效期及必要的现场恢复证据，再执行实际业务命令。审批通过但业务条件已变化时显示“结果已收到，业务待处理”，不能强行改变状态。

审批结果必须匹配业务对象、申请版本及审批实例。重复结果幂等，旧结果或乱序结果不能覆盖新申请；正式接入时在服务端验证来源及签名，不信任浏览器提交的 approved 字段。

外部审批通过不替代技术验收、逐问题验证、隐患复查或专业限制放行。EAM 仍记录相关业务结论和证据；其中需要审批的决定可引用外部审批结果。

## 页面与待办

业务详情展示审批状态、实例编号、申请版本、提交时间、结果时间、审批意见，以及刷新结果/查看外部审批入口。外部入口须由服务配置提供，不能接受任意用户输入 URL。

工作台“终止待审”展示外部审批状态及授权可见事项；审批操作入口由外部服务提供。EAM 不自行计算谁可以审批，也不复制外部节点待办。结果生效后，工作台从业务来源重新聚合后续执行安排。

## 候选记录与接口

| 对象 | 候选字段 |
| --- | --- |
| 业务审批关联 | business_type,business_id,application_id,application_revision,business_revision,external_instance_id,external_definition_key,approval_status,submitted_by/at,result_version,result_at,result_comment,result_evidence_ref |
| 结果消费记录 | external_event_id,external_instance_id,application_revision,result_version,received_at,applied_at,apply_status,apply_error,idempotency_key；按集成需要保存，不是审批流程节点表 |

| 模拟接口约定 | 用途 |
| --- | --- |
| POST /approval-adapter/applications | 模拟提交业务申请，返回外部实例引用；请求带业务版本、申请快照及幂等键 |
| GET /approval-adapter/instances/{id}/result | 异步读取预定义 JSON 审批结果与结果版本 |
| POST /work-orders/{id}/termination-applications | EAM 业务申请命令；保存申请与逐问题承接，不直接终止 |
| POST /work-orders/{id}/apply-approval-result | EAM 消费已验证的模拟回执；重新校验业务条件后生效 |

以上为正式设计候选契约；本次已实现的原型路径见下表，未实现的通用提交路径不能视为已接通；外部实际路径和正式数据库在后续统一设计时确定。正式消费可采用回调、事件或主动查询，当前原型先以查询模拟。

## 后续验收

覆盖提交失败保留输入、审批中禁止冲突操作、通过生效、驳回后恢复业务处理、旧版本不生效、重复回执幂等、外部失败可重试，以及结果生效后的工作台更新。生产接入另外验证来源鉴权、回执完整性及事务一致性。

## 本轮实现与验收（2026-10-11）

预定义回执位于 `prototype/mock/approval-data.js`，仅包含 pending/approved/rejected/withdrawn/failure JSON。页面通过异步模拟接口读取，不建设审批节点或审批任务分配。

| 已实现模拟路径 | 内容 |
| --- | --- |
| POST /work-orders/{id}/termination-applications | 校验申请快照及逐问题安排，保存外部实例引用；原业务状态保留 |
| GET /approval-adapter/instances/{id}/result | 查询维修外部回执样本及关联版本 |
| POST /work-orders/{id}/apply-approval-result | 从预定义样本消费结果，忽略客户端 approved；通过后重验问题版本、控制期限及恢复条件 |
| POST /maintenance/tasks/{id}/request-termination | 保养原申请入口保存外部实例引用，暂停并锁定执行 |
| GET /maintenance/tasks/{id}/approval-result | 查询保养外部结果样本 |
| POST /maintenance/tasks/{id}/apply-approval-result | 消费保养回执并生成后续执行安排；原 review-termination 路径为兼容别名，仅样本结果可决定状态 |

维修详情显示实例、申请版本、结果意见及生效状态；可选择模拟外部结果并获取。待审批锁定冲突动作；通过但问题版本或期限变化显示业务待处理，可更正后重提新申请。驳回与撤回不终止设备工单。终止保留问题状态和安全限制。工作台从来源记录读取终止待审/业务待处理入口，无自建审批人员计算。

候选字段追加：terminationApproval.snapshot、requestPayload、idempotencyKey、businessRevision、applicationRevision、instanceId、resultVersion、applyStatus、applyError、appliedAt；保养 termination.instanceId、externalStatus、businessRevision、resultVersion。保养撤回当前映射为不批准，externalStatus 保存 withdrawn，后续须重新安全复核才可恢复。

通用 POST /approval-adapter/applications 尚为候选路径，本轮由各业务申请命令模拟返回实例。没有实际外部服务地址，故不展示不可用的“外部审批”链接；正式集成时配置可信入口。当前回执消费主体是具有 EAM 业务处理权限的人员，并非外部审批人；正式服务仍须补来源鉴权、签名、回调事务与重试。

本地接口测试150/150通过；页面初始化回归30/30通过。本轮未验证真实外部服务，也未新增浏览器视觉验收证据。

## 业务闭环验收更新（2026-10-11）

保养通过回执无法生效时保存 applyStatus=blocked / applyError，并允许更正重提；工作台提供“更正终止申请”入口。外部决定来源与 consumedBy/consumedAt 分开记录，消费人不视为审批人。最新结果与剩余执行窗口缺口参见《业务闭环验收矩阵与问题记录》。
