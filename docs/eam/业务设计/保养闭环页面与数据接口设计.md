# 保养闭环页面与数据接口设计

日期：2026-10-11。状态：设计稿，尚未实现新HTML、模拟写接口或正式表。本稿衔接现有设备档案、共享列表组件、异常分诊和维修工单；后续全部模型完成后统一正式数据库/API。

## 目标与边界

现有保养页签仅展示归档样本，未具备计划派生任务和独立验收。本轮目标为“计划发布→任务生成→个人执行→独立验收→档案回读”，保养发现异常进入现有异常事件中心，后续核实分诊到缺陷/故障/隐患，再按需要关联维修。不得将保养完成直接推断为故障恢复、问题关闭或安全限制解除。

采用独立保养计划与保养任务菜单，档案保养页签聚合查询并链接原单。不把所有操作塞入档案，不将保养任务伪装成维修工单。计划支持多个岗位或人员作为候选范围；每项任务必须有一名明确主责，可配置多名协作人员，候选人员不能自动全部成为执行人。发布时选明“指定主责”或“主管派工”；主管派工任务为待派工，不允许无人开工。

## 状态和异常流程

计划：草稿→待审核→已发布；退回回草稿；已发布→暂停→已发布；已发布/暂停→已终止。发布后修改生成新版本，已有任务继续引用原快照；待审核不可派生任务。

任务：待派工→待执行→执行中→待验收→已完成；执行中↔已暂停；验收退回回执行中并增加执行版本。待派工/待执行可由主管取消并留原因；已开工不得直接删除或取消，应暂停并形成终止申请及独立审核，获批后为已终止。已完成/已取消/已终止为终态。暂停/终止不计作成功保养。

异常：执行人员提交异常发现，携带equipmentId、sourceTaskId、sourceItemId和执行版本；重复提交相同业务键返回原记录。核实分诊沿用现有流程；任务关闭不关闭关联问题。验收判断保养内容是否完成及遗留事项是否明确，不能代替专业问题复核或作业许可解除。

## 周期与人员规则

首批时间周期明确频次单位（日/周/月）、间隔、开始日期、工厂时区、执行窗口及逾期口径。按计划锚点推算下一计划窗口，成功完成时间单独保存，不因提前/延期执行默默漂移周期。同计划版本、设备、计划窗口生成键唯一；重复触发不重复建任务。跨月无该日期按当月最后一天，规则显示在计划详情。停用/报废设备不自动派生任务，记录跳过原因。

计时/计次触发作为后续类型：需有效测点、累计基准、单位、采样质量及重置处理，未接入前不允许发布该类型。组合触发须明确任一/全部，不能与时间型混写成自然语言频次。暂停计划不删除已生成任务；恢复前预览遗漏窗口，首批默认不补发历史逾期任务，补发须人工选择窗口和原因。

人员关联包括岗位/人员ID、组织范围、有效期、主责/协作角色。任务派工校验当前有效人员、资格、安全许可；重派保留前后指派与理由，执行中重派须主管授权。人员配置变化不覆盖已执行任务的人员快照。

## 候选模拟接口清单

| 接口 | 用途/校验 |
| --- | --- |
| GET /maintenance/plans、GET /maintenance/plans/{id} | equipmentId、status、keyword、page/pageSize；返回授权items/total/actions |
| POST /maintenance/plans、PATCH /maintenance/plans/{id} | 创建/编辑草稿；expectedRevision及必填项目规则 |
| POST /maintenance/plans/{id}/submit、/approve、/reject、/pause、/resume、/terminate | 状态/独立审批/原因；发布产生不可变版本 |
| GET /maintenance/plans/{id}/generation-preview | 窗口及跳过原因，无写入 |
| POST /maintenance/plans/{id}/generate | 明确窗口、发布版本、幂等键；设备及人员校验 |
| GET /maintenance/tasks、GET /maintenance/tasks/{id} | 设备/人员/状态/时间范围；返回版本、项目快照、操作许可 |
| POST /maintenance/tasks/{id}/assign、/start、/pause、/resume | 派工/开工/暂停恢复；expectedRevision、原因、安全依据 |
| PATCH /maintenance/tasks/{id}/execution | 暂存当前执行版本，逐项证据与异常引用 |
| POST /maintenance/tasks/{id}/submit、/accept、/reject | 必填结果、试运行及独立验收；不关闭关联问题 |
| POST /maintenance/tasks/{id}/cancel、/request-termination、/approve-termination | 未开工取消或已开工独立终止审核，不物理删除 |
| POST /discoveries | 复用异常入口并记录保养来源引用及幂等键 |
| GET /equipment/{id}/domains/maintenance | 聚合同源计划/任务/验收和旧历史样本；返回来源详情链接 |

所有接口所需主数据、规则、记录与示例初始状态放入mock JS预定义JSON。独立HTML绑定异步request获取数据；控制器不自造样本，不通过直接读取localStorage绕过模拟接口。命令返回业务版本；HTTP/模拟错误区分FORBIDDEN、CONFLICT、VALIDATION、NOT_FOUND，失败保留用户输入。

## 分批落地与验收

第一批：计划列表/详情、时间规则、多人岗位范围、发布审核及生成预览。第二批：任务列表/执行、个人派工、安全开工、异常来源。第三批：独立验收、终止审核、档案同源聚合和往返。

每批同时记录页面→字段/表关系→接口→状态按钮→权限，完成模拟单元检查及关键PC/移动浏览器链路。必须覆盖非法状态、版本冲突、重复生成、跨设备隔离、无人主责、执行人自验、暂停/恢复窗口和异常未结不被关闭。只有查到对应命令与界面按钮并跑通流程后，才能将矩阵中的“保养展示”提升为“业务闭环”。
