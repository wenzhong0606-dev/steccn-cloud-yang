## 范围与交付边界

本批增加两个独立页面：maintenance-task-list.html（保养任务）、maintenance-task.html（保养执行与详情）。计划详情的窗口预览增加可选窗口及明确“生成任务”操作，生成成功返回任务引用，并链接任务清单。任务主责精确到个人，协作可多人；主管派工生成待派工，指定主责生成待执行。

任务执行包括暂存、开工、暂停/恢复、上报异常、提交完工。提交后是待验收，不是已完成。第三批独立验收、终止审核、完整档案同源聚合仍待实现；本批不得产生已完成状态或用工单验收代替保养验收。已开工任务不提供删除/直接取消；未开工任务可主管取消且记录理由。本批展示已开工终止需走独立审核，终止命令第三批再接入，不能用暂停冒充终止。

复用首批公共筛选组件：无关键词前缀，高级筛选漏斗图标；标题/面包屑、input-group、工具图标、DataTable/load-status/表内空态/分页/行内操作统一。任务导入无完整业务校验则禁用；导出读取接口授权范围全部数据。

## 状态、角色与下一步操作

| 状态 | 授权角色 / 人员 | 实际按钮和迁移 |
| --- | --- | --- |
| 待派工 pending_assignment | 主管 | 指派主责及协作→待执行；未开工取消→已取消 |
| 待执行 ready | 主管；任务主责/协作只读派工 | 主管重派；主责安全确认并开工→执行中；主管取消→已取消 |
| 执行中 in_progress | 指定主责和授权协作；主管 | 执行人员保存逐项结果/上报异常；主责暂停→已暂停，提交完工→待验收；主管执行中重派需原因并保留执行者快照 |
| 已暂停 paused | 主责/主管 | 原因与安全条件复核后恢复→执行中；不解除专业限制 |
| 待验收 pending_acceptance | 授权查看 | 只读当前提交版本、证据及异常关联；独立验收在第三批，明确标识待接入 |
| 已取消 cancelled | 授权查看 | 查看取消原因与审计，无再次执行按钮 |

权限同时校验人员实际角色、设备授权范围、任务参与人及命令状态；不能靠按钮隐藏。指定主责变更不篡改先前结果actorId。暂停恢复与安全开工的前提是模拟接口返回实际许可依据，不能只用一个前端复选框放行。

## 任务生成规则与快照

1. 只能选择当前有效发布快照的计划窗口；修订未批准时仍使用旧发布版。生成请求带planId、activeVersion、expectedRevision、windowKeys、reason、idempotencyKey，服务端重新计算窗口，不接受前端伪造日期/设备/项目。
2. 固定锚点和Asia/Shanghai时区沿用首批规则。明确选择窗口，不静默补发所有过去逾期窗口；过去窗口须单独确认补发理由。暂停/终止计划不能生成，设备非在用、人员范围失效等跳过项不可勾选。
3. versionWindowKey保持发布版本/设备/计划窗口唯一；另用occurrenceKey（逻辑planId、equipmentId、scheduledAt）防止跨版本重复生成同一日期任务。已生成任务不得被修订或再生成覆盖。
4. 相同幂等键相同请求返回原结果；相同键不同请求返回冲突。并发/不同幂等键选同一窗口也只能返回同一任务；模拟层命令提交串行化或版本锁保障，不能只依赖前端禁用按钮。
5. 任务保存时间规则、项目、人员候选、有效期、计划版本、安全要求及设备关键引用快照。任务指派按当时有效人员解析，保留bindingRefs/resolvedPeople/assignedBy/At；任务开工前再次检查人员资格和许可，不以计划发布时间的资格替代开工资格。
6. 候选多人/岗位不复制生成多人任务。每设备每窗口一项任务、一名主责、零至多名协作；主管派工任务不得无人开工。
7. 计划暂停/终止不删除已生成任务；已生成任务仍按原状态和快照管理。所有操作使用revision，旧版本提交拒绝。

裁决：跨版本occurrenceKey是对首批同版本唯一规则的补充，防止同一日期在修订批准后再次派发；不回写已生成任务的版本和项目。周期策略改变产生的新日期如需与既有任务合并，首批仅提示潜在重叠，由主管安排，不擅自合并。

## 异常创建与关联边界

任务项异常指向既有异常事件中心discoveries。来源字段为sourceType=maintenance、sourceTaskId、sourceItemId、executionVersion、equipmentId及证据，发现状态仍为submitted，由现有核实分诊流程处置。

新增POST /maintenance/tasks/{id}/discoveries作为模拟协调命令，先校验任务、权限、设备与执行版本，再以稳定来源业务键调用problem-api创建发现，再登记关联。problem-api保存真实来源字段，不能只拼在描述中。

跨mock对象不假称数据库原子事务。持久化关联请求状态（pending_link/linked/failed）和幂等请求键；如果发现创建成功但任务关联失败，返回原发现引用及待重试状态，页面提供“重试关联”，不重复创建发现，不把异常误判为未上报。读取任务显示待关联记录，阻止无关联证据的异常项目提交完工。正式实现阶段候选使用同事务或可靠消息/outbox统一设计。

任务完工可关联未关闭发现，但必须有实际发现ID和后续处置说明；只表达保养执行完成，不能改变发现/缺陷/故障/隐患状态，也不能解除许可或限制。计划/任务的试运行不替代故障恢复独立验证。

## 候选模拟接口

- GET /maintenance/tasks：equipmentId、status、mine、keyword、page/pageSize；返回授权items/total/actions。
- GET /maintenance/tasks/{id}：任务、原发布快照、执行版本、参与人员、异常关联及审计。
- POST /maintenance/plans/{id}/generate：activeVersion、expectedRevision、windowKeys、reason、idempotencyKey。
- POST /maintenance/tasks/{id}/assign：expectedRevision、primaryPersonId、collaboratorIds、reason。
- GET /maintenance/tasks/{id}/start-check：资格/设备/许可/控制要求的当前检查，不写业务状态。
- POST /maintenance/tasks/{id}/start、pause、resume、cancel：expectedRevision、reason、许可/确认快照。
- PATCH /maintenance/tasks/{id}/execution：expectedRevision、executionVersion、逐项结果、工时、用料引用、试运行。
- POST /maintenance/tasks/{id}/discoveries：task/item/version来源、发现描述、优先级、证据及幂等键；协调既有POST /discoveries。
- POST /maintenance/tasks/{id}/anomaly-links/{id}/retry：重试待关联请求，不重新创建发现。
- POST /maintenance/tasks/{id}/submit：expectedRevision、executionVersion及完工原因；完整性校验后待验收。

通用错误FORBIDDEN/CONFLICT/VALIDATION/NOT_FOUND/LOADING/ERROR沿用；返回对象副本，失败保留输入。业务写入不通过直接操作localStorage模拟；持久化只在API适配层。
