# 角色工作台与终止后续闭环设计及验收矩阵

日期：2026-10-11。本批以现有原型为基础，不创建正式数据库或生产接口。

## 本批范围与角色

工作台使用独立 HTML、公共页头、列表容器、表格状态及分页组件。业务数据通过 JS 预定义数据和异步模拟接口读取；聚合结果不另建待办状态存储。

| 身份 / 职责 | 展示内容 | 操作入口 |
| --- | --- | --- |
| 点检 / 运行执行人员 | 本人点检及专项检查 | 点检执行页，任务或专项 ID |
| 维修 / 外包执行人员 | 本人维修、保养、退回重做；本人后续责任 | 工单 / 保养任务详情 |
| 主管 | 待派工、逾期保养、允许本人独立审核的终止及验收 | 对应详情的派工、审核、验收表单 |
| 验收职责人员 | 来源接口允许的独立验收、后续复核 | 保养任务 / 工单验收页 |
| 设备负责人 | 所辖设备未结异常、缺陷、故障、隐患、后续安排和限制 | 来源问题详情或后续安排 |
| 安全人员 | 隐患、专业限制 | 隐患核实、控制、复查、独立放行 |
| 其他角色 | 当前身份与设备范围下的实际责任事项；无事项显示表内空态 | 不因工作台展示获得额外审批权限 |

角色不是岗位，也不是设备负责人属性；负责人按设备 ownerId 判断。兼任角色以当前角色上下文读取，人员可以切换其已登记角色。本批不虚构独立“验收人”平台角色。生产设备范围必须由服务端身份授权注入；原型未指定 equipmentIds 时采用模拟设备目录范围。

## 聚合与刷新

`GET /workbench` 聚合点检会话查询适配器、保养任务接口、异常/缺陷/故障/隐患/维修接口。保养列表逐页读取，统一输出来源、业务 ID、设备、责任人、期限、状态、动作和跳转参数。点检适配器仍基于现有 JSON 初始化的会话模型，不代表已新增正式点检服务。

指标由实际行计算，删除旧固定数值。不同操作队列可能引用同一业务单，如未结隐患和有效限制；行键为来源、单号、职责类别，指标计数是待处理事项数，不是去重设备数。未设置期限明确显示“未设置期限”；来源失败显示来源和错误，指标显示“—”，不把读取失败当成零待办。手动刷新、页面恢复及重新可见时重新读取来源状态。

## 终止后的执行闭环

`终止申请 → 独立批准 → 后续待处理 → 责任人提交结果和证据 → 待独立复核 → 通过完成 / 退回处理`。

后续安排在原保养任务详情独立卡片内处理，也从工作台进入；原任务保持终止。批准终止生成唯一后续对象，继承安排、责任人、期限、遗留风险、控制措施及终止引用。已存在的批准终止会话记录在读取时按原批准信息补齐后续对象，不伪造完成结果。

责任人才能提交；复核使用现有验收角色并排除责任人，须提供意见及证据。命令携带任务数据版本与执行版本，旧版本、无权限、无证据拒绝。每次提交和复核保留历史。此对象完成只表示后续安排已执行并经复核，关联异常仍从下方异常列表处理，设备限制仍由状态与许可或隐患流程独立解除。不得用后续完成替代异常归档或限制放行。

## 后续仍需补齐

本批聚焦工作台和保养终止后续安排。维修终止后的逐问题重新派单、后续任务引用的存在性校验、控制有效期限和升级策略仍需继续审计；工作台中的问题入口不能替代这些源业务守卫。点检专项由既有来源模型处理，尚不包含新的点检终止审核流程。全量现有功能验收矩阵还需扩展到其他业务模块。

## 2026-10-11 第二步：维修终止的逐问题承接

终止前须对全部未关闭问题提供唯一承接安排，带问题版本、责任人、期限、控制措施及有效期。可引用同设备同问题已审核活动后续工单，也可由有处置职责的问题责任人直接承接，在问题页面执行、必要时重新建单。已开工仍须现场恢复及证据；已验收仍只能业务关闭。接口在事务副本内验证全部安排再提交，失败不保存部分转交。

原工单展示承接清单及后续工单/问题入口。问题主责和期限同步更新，问题状态及设备限制不自动改变；原隐患控制有效期须覆盖新期限。逐问题承接在工作台沿原问题来源聚合，不复制独立任务状态。

候选字段：eam_work_order.cancelled_by/at,cancel_reason,site_restored,cancel_evidence_refs；eam_problem_followup_arrangement.source_order_id,problem_type,problem_id,expected_problem_revision,owner_id,due_at,control,control_until,followup_order_id,arranged_by/at；历史另存，保留历次承接。扩展模拟 POST /work-orders/{id}/cancel 的 residuals 参数，包含上述逐问题字段，正式候选为 POST /api/eam/v1/work-orders/{id}/terminate。

验收新增：漏项、控制过期及重复终止拒绝；失败原子回滚；成功后问题状态与限制保留、主责期限更新。维修终止承接及既有维修/隐患规则15项测试通过。早先“维修终止逐问题承接待审计”条目已由本节更新，控制升级策略、完整多设备业务数据仍待后续。

## 续批浏览器验收证据

工作台实测1366×768、390×844和1024×600。页面无整页横向溢出，表格保留内部横向滚动；移动端换页从14条第1页切到第2页6条，分页底部628.75px，底部导航上缘783.20px。低高度分页可滚动到达，底部396.78px低于导航上缘543.20px。截图保存在[验收证据目录](../验收证据/角色工作台/主管工作台-PC.png)。

浏览器确认点检人员与班组长工作台展示不同队列，班组长待技术验收入口存在；终止操作打开包含DF-1001、FL-1001、HZ-1001的逐问题承接表单。表单仅查看并取消，未提交或改写用户浏览器业务记录。浏览器错误日志为空；模拟角色已恢复为点检人员，临时视口已恢复，测试标签页已关闭。

实测发现并修复：点检窗口结束日期遗漏、工作台状态字典部分英文状态、移动端指标占用过高（改为两列）、刷新按钮不与筛选同组（并入公共input-group）。工作台配置和API资源统一更新版本后，移动端配置加载恢复正常。

本地规则/接口测试146项通过，30页实际脚本初始化和无图片设备回归通过；文档一致性及样式门禁零错误。浏览器证据只覆盖上述关键页面和交互，不代表全部页面E2E或生产后端验收。

当前维修终止仍由工程师/主管直接执行，未新增独立的维修终止申请审批状态；工作台“终止待审”来源目前是保养审核流程。若统一维修终止为申请—独立审核，需要另行补齐工单状态、权限、拒绝恢复及历史记录，不能把本轮承接守卫称为该审批流程已经完成。

## 2026-10-11 审批边界更新（当前有效）

用户明确申请/审批流程由外部审批服务提供。下一步调整为外部审批结果模拟适配与EAM业务结果消费，不建设独立审批服务。上文维修终止审批缺口是集成与业务状态适配缺口，并非自建审批引擎任务。具体候选字段、接口、结果版本及待办边界见[外部审批约定](外部审批集成与模拟结果接口约定.md)。当前代码尚未完成该适配。
