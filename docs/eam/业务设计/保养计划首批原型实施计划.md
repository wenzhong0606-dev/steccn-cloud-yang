# 保养计划首批原型实施计划

日期：2026-10-11。状态：首批已实施；实际完成与边界见交付记录。

**目标：** 实现可维护、可审核发布、可预览计划窗口的保养计划原型。

**执行方式：** 建议在当前会话逐项实施；本批不用子代理、不提交Git、不改正式后端。

**设计依据：** [保养闭环页面与数据接口设计](保养闭环页面与数据接口设计.md)。

**架构：** 独立列表和详情HTML提供页面骨架及表单；JS控制器绑定节点，异步mock API读取预定义JSON并执行规则；接口层负责角色、状态、版本、审核与事务审计。复用当前Bootstrap5共享组件，不增设第二套导航/列表/分页样式。

**技术：** HTML、Bootstrap5、本地JS、Node内置test、现有浏览器验收工具。

## 范围和约束

本批只实现时间型计划、草稿维护、独立审核、暂停/恢复/终止以及生成预览。不实际创建任务，不添加无法工作的“生成任务”按钮。任务生成、执行、验收与档案聚合在后续批次落地。

发布计划保存不可变版本，已发布不能原地修改；“修订”复制为新草稿，审核通过前旧版本继续有效。旧版本留在版本历史，列表按当前有效版本和待审草稿展示明确状态。计划暂停/终止必须提供理由；当前未实现任务生成，因此不宣称处理了已生成任务。

所有需要接口的数据/方法放入mock层。控制器不直接读写存储；sessionStorage仅由API作为会话持久化适配器使用，键名eam-maintenance-v1，独立schema版本及初始化样本，不改现有用户会话键。

文档中文命名，存docs/eam；检查工具存tools/eam；证据存页面设计/维护业务原型。既有未提交文件和网关/Nacos配置保持原状。正式建表、接口发布、实时调度均不在本批。

## 任务一：规则与模拟接口

- [ ] 先写失败测试，验证未提供实现时测试失败；禁止通过直接修改样本来绕过命令。
- [ ] 定义三个主要样本：EQ-001在用计划、EQ-001待审计划、第二设备草稿；岗位及多人范围有实际映射，不把岗位ID当人员ID。
- [ ] GET /maintenance/config 返回候选设备、岗位、人员、周期单位、规则说明；GET /maintenance/plans支持equipmentId、status、keyword、page/pageSize和权限items/total/actions；GET /maintenance/plans/{id}返回版本、项目、绑定、审计及操作许可。
- [ ] POST /maintenance/plans创建草稿；PATCH /maintenance/plans/{id}编辑草稿，expectedRevision必填。校验名称、设备、日期、正整数间隔、项目完整性、人员范围及主责策略。
- [ ] 实现POST /maintenance/plans/{id}/submit、approve、reject、pause、resume、terminate、revise；每个命令要求预期版本、理由和授权，审核人不得等于提交人。
- [ ] 响应返回对象副本；拒绝命令不得写入记录或审计。成功命令审计含前后快照、人员、时间、原因与版本。
- [ ] 失败场景返回VALIDATION/FORBIDDEN/CONFLICT/NOT_FOUND；loading按项目现有模式处理，不能当作空数组。浏览器使用异步延迟，不由控制器伪造结果。
- [ ] 跑Node测试验证：角色越权、同人换角色自审、缺项目/无人主责、非法状态、旧版本、发布后不可编辑、修订不改历史、跨设备过滤、拒绝无写入、刷新持久化。

周期预览GET /maintenance/plans/{id}/generation-preview?from=YYYY-MM-DD&to=YYYY-MM-DD：只允许已发布版本；范围限366天、最多100个窗口，超限返回校验错误，不静默截断。返回计划版本、设备、scheduledAt/windowStart/windowEnd、windowKey和跳过理由。草稿详情另显示日期规则说明，不能预览伪装成可执行发布计划。

日期按工厂Asia/Shanghai日期计算，不以浏览器时区或当前电脑UTC偏移漂移；时间锚点固定，月末按当月最后一天。窗口跨度必须非负整数且前后天数合计小于相邻周期最小跨度，避免同一计划窗口重叠。接口测试覆盖闰年、1月31日到2月、跨年、边界窗口、预览无写入和停用设备跳过。

## 任务三：详情表单和审核闭环

- [ ] 基本信息：编号只读、名称、设备、责任组织、状态、版本、说明。
- [ ] 时间规则：日/周/月、间隔、锚点日期、窗口前后天数、时区只读，显示明确周期说明。未接入计时/计次不作为可发布选项。
- [ ] 保养项目：按顺序维护项目名称、部位、方法、标准、结果类型、单位/上下限、必填及证据要求；可新增/移除草稿项目，发布后显示快照。
- [ ] 人员范围：岗位/人员多选、主责策略、指定主责、协作候选、组织与有效期。指定人员必须在有效范围内；主管派工明确“任务生成后待派工”。
- [ ] 表单由JSON config填充选项；详情读取后按API actions决定编辑/审核/暂停等按钮，权限不能仅靠隐藏按钮。
- [ ] 保存/提交按钮防重复；校验错误定位字段并保留输入，失败/冲突保持表单，提供重新读取前未保存提示。
- [ ] 审核弹窗展示待审版本及提交人，批准/退回均必填意见，审核成功刷新详情/历史；同人不能通过换角色审核。
- [ ] 已发布提供修订、暂停、终止、预览；暂停提供恢复/终止；终止只读；不提供无依据的物理删除。
- [ ] 预览显示查询窗口与设备跳过原因，清楚标注“未生成任务”；与表格统一状态/分页，不新增第二套空态。
