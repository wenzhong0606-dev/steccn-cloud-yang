# 保养闭环第三批实施计划

日期：2026-10-11。用户已明确授权“继续完成第三批”，在当前原型目录连续实施，不另设确认环节、不提交Git或改正式后端。

## 范围与顺序

1. 独立验收接口：待验收→完成或退回。校验实际角色、所有本次参与者、数据/执行版本、项目及试运行复核、证据及遗留异常评审。退回冻结历史、增加执行版本、清空本次结果，安全复核后重新执行。
2. 终止接口：已开工执行中/暂停→申请终止并暂停→独立批准为已终止或驳回保持暂停。申请包含已完成工作、遗留风险、控制措施、后续安排/责任人/期限/证据；审查者不能是申请人或执行参与者。审核中禁止重派/恢复/提交等旁路操作。
3. 独立maintenance-acceptance.html队列，区分待验收/终止待审核，复用标题、工具栏、弹窗筛选、Table/load-status/分页。任务详情接入验收/终止表单和历史快照。所有配置与数据预定义JS JSON，读写通过模拟API。
4. 设备档案保养页签替换旧样本，异步聚合授权计划、任务、提交/验收、终止记录；跳转对应来源页保留设备/页签/端型上下文。生命周期/审计纳入同源保养事件，设备总览保养数量同源。
5. 先失败测试覆盖独立性、旧版本、验收退回重做、终止审核/驳回、异常不关闭、同源读数/设备隔离/持久化；浏览器三条实际路径和PC/移动尺寸验收。逐页候选字段与接口登记、菜单/总表/进度/证据保存。

## 实施决策

- 退回后状态为暂停，新增执行版本需重新复核许可后恢复，比早期概念状态图直接执行中多一次安全确认；旧记录只在历史快照中查看，不复用旧结果冒充重做。
- 验收/终止统一队列入口，独立业务命令表单在任务详情，只维护一套命令UI。验收记录与终止记录是独立对象，不另建维修工单或按页面分表。
- 验收通过/终止批准不关闭发现/缺陷/故障/隐患、不放行设备限制。尚未接入真实调度、数据库与后端，候选结构待全部模型完成后统一设计。

## 候选接口和记录

GET /maintenance/reviews（type、equipmentId、keyword、page/pageSize）；POST /maintenance/tasks/{id}/acceptance（expectedRevision、executionVersion、decision、reason、itemsVerified、trialVerified、evidence、residualReview）；POST /maintenance/tasks/{id}/request-termination（expectedRevision、executionVersion、reason、completedWork、residualRisk、controlMeasures、followup、followupOwnerId、followupDueAt、evidence）；POST /maintenance/tasks/{id}/review-termination（expectedRevision、executionVersion、terminationRevision、decision、reason、confirmed）。

候选maintenance_acceptance、maintenance_submission、maintenance_execution_version、maintenance_termination_request/review、execution_participant；task新增completedAt/terminatedAt，审核审计保存人员/角色/前后快照。同源档案是读取投影，不另建保养档案业务表。
