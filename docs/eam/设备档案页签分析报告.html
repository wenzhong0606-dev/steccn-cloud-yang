三、跨页签共性发现与优化建议

① 全局 tab handler 三方叠加（已登记「作用域化」待办）

archive-page.js:73（全文档 [data-tab]）、interactions.js:10-13（全局）、ui.js:5（按 6 个 .tabs 组装饰为独立 tablist）三套 handler 并存。本页因 tab 值唯一、面板无嵌套组而功能正常，但 ui.js 把导航组当成独立 role=tablist 且方向键不跨组，ARIA 模型与「单面板」事实不符；任一页出现第二组同名/嵌套 tab 即串扰。建议：以 archive-page.js 的 selectTab 为唯一真相源，删除 interactions.js 的全局绑定，并让 ui.js 对「nav 型 tab」跳过装饰或改为单 tablist。

② 记录型页签高度同质（一致性好）

16 个页签共用 loadPanel()→renderRows()：搜索 + 状态/来源筛选 + 分页 + 详情弹窗，UX 高度一致，维护成本低。这是本页最稳健的设计。

③ 摘要组件分布不均

仅 parameters / structure / trend / history 4 个页签有 data-business-view 摘要；bom / meters / risk / cost / related / audit / installation / work / failure / repair / media / documents / completeness 共 13 个无摘要。建议评估是否为高价值页签（如 risk 合规、cost 成本）补摘要卡。

④ 跨链缺失造成信息断点

bom / meters / risk / cost / related / audit 6 个页签 .actions 为空，与其它域本可关联（BOM↔更换费用、计量器↔趋势、合规↔标准、审计↔各操作页签）却无入口。建议在相关页签补 1–2 个跨链，形成横向导航网。

⑤ state 面板的 restrictions 渲染路径例外

「使用限制」是独立 domain，却内嵌 state 面板并走单独 api('domains/restrictions')（第 65 行），未纳入统一 loadPanel()。建议抽为共享渲染助手，消除双路径。

⑥ media 的 3D 为占位、且非记录型

3D 仅 CSS 概念示意（未接 GLB/glTF）；media 面板结构与其余记录型页签差异大。若产品要求真 3D，需单独排期；否则建议明确标注「示意」以免误导。

⑦ 深链与权限控制到位

selectTab 写 ?tab= 并 history.replaceState（第 51、87 行），支持深链与刷新定位；上传/编辑受 canEdit/canLifecycle/canRelease 控制。这两点是本页的亮点。
