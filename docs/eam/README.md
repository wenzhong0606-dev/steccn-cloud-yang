## 目录职责

- `业务设计/`：对象职责、流程、状态及业务验收；`数据设计/`：候选实体字段及逻辑关联。
- `页面设计/`：交互、页面规格；`页面设计/页面记录/`：逐页候选字段/API；`页面设计/设备档案重设计/`：档案专项。
- `prototype/`：HTML/JS/CSS与模拟接口可运行原型，**不能当作正式应用代码**。
- `验收证据/`：已发生的测试输出和截图（按当时版本解释）。
- 旧实施计划、修复前审计、阶段交付记录保留作追溯材料，不再作为最新待办或最终规范；避免未核对交叉引用便批量删除。

## 变更治理

1. 任何功能/页面变更必须同步修改逐页登记与当前状态；每条功能标注【需求/模型/原型/真实实现/已验收】。
2. 发现内容冲突时，业务语义以业务基线为准、页面缺口以最新逐页产品审查为准、测试状态以对应验收证据为准；不得以最新文档的日期替代实证。
3. 物理表结构、正式接口、权限注册、消息集成、外部审批回执鉴权和CI均需独立审查确认；不得沿用模拟测试结论推定已完成。
4. 删除历史文件前核对反向引用、唯一业务规则和验收用途；需保留的历史资料可以保留并在目录入口显式标为「历史证据」。
