# 保养计划列表—页面数据与接口记录

页面：maintenance-plan-list.html；阶段：候选记录及异步JSON模拟原型，尚未正式建表。

## 操作与角色

列表关键词/弹窗高级筛选、分页、权限范围导出、列设置、刷新、新增；导入禁用。合法人员角色映射由接口校验，不能伪造角色或人员。所有合法EAM人员可只读计划；工程师/主管维护，主管/经理独立审核，提交人不可自审。无物理删除已发布计划，終止保留原因及历史。草稿数据revision与业务planVersion分开。

## 候选表与字段

maintenance_plan：id、code、name、equipmentId、organization、status、revision、planVersion、activeVersion、activeStatus。
plan_revision：周期unit/interval、anchorDate、timezone、windowBefore/After、assignmentMode、primaryPersonId、assignmentValidFrom/To、submittedBy、approvedBy/At。plan_item：id、顺序、name、part、method、criterion、resultType、unit、min/max、required、evidenceRequired。plan_assignee：planRevisionId、type(position/person)、id及范围有效期。plan_audit：action、actorId、reason、at、revision、before/after。

已发布版本保存项目/人员/时间规则快照；修订期间旧版有效状态独立保存，可暂停恢复。修订不能更换设备。列表、详情及预览都是同一对象投影，不按页面各建业务表。设备候选由模拟接口投影现有设备台账会话；Node隔离样本中第二设备仅用于规则验证。

## 候选接口列表

GET /maintenance/config；GET /maintenance/plans（equipmentId/status/unit/keyword/page/pageSize）；GET /maintenance/plans/{id}；POST /maintenance/plans（idempotencyKey）；PATCH /maintenance/plans/{id}（expectedRevision）；POST /maintenance/plans/{id}/submit、approve、reject、pause、resume、terminate、revise（expectedRevision/reason）；GET /maintenance/plans/{id}/generation-preview（from/to）。同一maintenancePlansV1接口组支持两页。

错误分VALIDATION/FORBIDDEN/CONFLICT/NOT_FOUND/LOADING/ERROR；失败不改变数据，页面保留输入。创建使用空白JSON草稿模板，不从完整样本补足必填项目。数据在mock/maintenance-data.js预定义；rules/api实现规则及异步request；页面控制器只绑定HTML。

## 展示及边界

标题/面包屑、筛选、DataTable、load-status、表内空态、分页与行内按钮复用共享组件；工具图标和列可见性也由共享组件提供。PC主内容可纵向滚动；移动表格内部横向滚动，长内容截断，主副标题各自一行。窗口预览只读，不生成任务；计划导入未实现校验审批，因此明确禁用。导出按接口授权范围翻页读取全量JSON。

人员有效期当前按整个候选范围设置，不支持每个绑定不同期限；协作分工和个人任务派工待任务批次。时区固定Asia/Shanghai；按JSON样本asOfDate显示下一窗口，非实时调度器。样本时间型仅支持日/周/月，计时计次不可发布。当前尚无真实调度、任务执行、保养验收及档案计划聚合。
