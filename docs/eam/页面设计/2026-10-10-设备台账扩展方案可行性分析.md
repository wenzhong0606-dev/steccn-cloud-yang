# 设备台账扩展方案可行性分析

> 后续决定已覆盖其中功能位置/槽位及旧推进顺序：取消这两类对象，保留所属位置与变更历史；分类参数独立菜单，档案按14页签组织。本文保留为历史设计依据。

日期：2026-10-10。依据：用户补充文本、当前device/equipment页面与逐页候选记录、SAP官方功能位置装拆说明、ISO 14224官方范围说明。此次为业务可行性分析，未修改HTML行为、正式数据库或接口；碳捕集、余热发电作为补充材料提出的适用场景，尚未认定为仓库已验证业务范围。

## 结论

建议采纳“设备主数据核心＋关联业务＋生命周期时间轴”的定位，技术可行，较当前以示例设备为中心的全景原型更适合商业化扩展。16模块作为业务覆盖清单，不能直接等同16张表、16个菜单或16个必填字段区。本方案是建议基线，未自动替代既有状态机与页面登记。

## 与当前设计的差距

| 能力 | 当前证据 | 建议处理 |
| --- | --- | --- |
| 身份与基础台账 | 已有设备ID、code、型号、责任人及CRUD | 补分类/类型、Tag、资产属性、编码历史；唯一性范围和编码变更规则先明确 |
| 层级与位置 | 已有位置/组成树、location_id候选及部位 | 补功能位置主数据、设备装拆关系和有效时间，不能以location_path字符串代表完整模型 |
| 参数模板 | 当前无完整分类参数模板对象 | 新增逻辑模板/定义/值/版本记录；设计、额定、允许范围与实时值分开 |
| 状态 | 已分生命周期、运行、健康、计量、使用许可 | 保留已有维度；管理冻结和盘点是独立流程标志，不替代安全使用许可 |
| 点检 | 已有标准/路线/计划版本及个人任务 | 补设备标准适用关系及差异审批；旧任务保留版本快照 |
| 保养与故障维修 | 工单/异常部分闭环，保养尚未完整模型 | 单独补保养业务、故障事件、停机区间；工单不等于故障事件 |
| BOM与可维修部件 | 有部位，完整BOM/序列化实例装拆未完成 | 分清物料、设计BOM、实际安装实例、替换记录，库存仍归仓储 |
| 制造采购投运 | 部分基础字段 | 补采购/验收/质保引用与投运审批证据，不复制完整采购流程 |
| 数采与运行 | 当前为模拟状态和趋势 | 测点映射、质量码、采集/接收时间及陈旧判定；高频数据由数采存储 |
| 安全合规 | 页面有风险/计量/许可设计切片 | 特种设备/计量设备适用项必须进入对应首期闭环，不能统一降为P1 |
| 成本与财务 | 当前仅概念关联 | 财务资产映射可多对多；费用来源、币种、含税及核算时间需明确，避免重复计费 |
| 文档与履历 | 多图/预览/权限/设备履历已模拟 | 继续沿用，补安装与移动业务事件；真实文件服务和3D仍后续集成 |

## 必须补足的关键规则

1. 身份：设备ID跨移位/维修保持稳定，业务编码可受控变更，Tag原则上与功能位置及有效期关联；新泵替换旧泵时不得继承旧实体ID。旧记录冻结当时编码、位置、名称快照。
2. 时态关系：独立设备父子关系、安装位置和责任分配带生效/失效时间；防循环、防不合法重叠。同一安装槽位的占用约束按业务配置，不能假定一个功能位置只能放一台设备。
3. 分类参数：模板定义单位、类型、精度、必填、范围及版本；设备级差异审批。范围校验不等于运行报警，报警规则单独管理。草稿允许不完整，发布/安装/投运按阶段校验。
4. 状态与数据源：人工/数采冲突有来源优先级、时效与仲裁；过期值标记未知/陈旧，不能沿用为当前正常。存在故障不自动报废，检修不自动解除使用限制。
5. 维护对象：电机有独立序列号与维修履历时作为可追溯实例；普通耗材作为物料。维修对象、影响设备、安装位置分别关联。故障与工单允许一对多/多对一，停机事件独立，统计按设备时间区间去重。
6. 主数据发布：新增草稿→校验/按需审批→有效；关键分类、参数、位置、责任变更留原因及前后值。批量导入应提供预校验、重复匹配、逐行错误、权限及撤销/补偿边界。
7. 平台复用：组织、人员、岗位、权限复用平台；财务、仓储、数采通过引用和来源契约接入。台账聚合接口按页签懒加载与分页，某来源失败不阻断其他页签，显示最后更新时间。

## 页面与角色设计建议

列表：设备树在PC左侧、移动端筛选抽屉；身份/类别/位置/多维状态/责任人作为默认列。动态参数列限于选定同一分类，跨分类不能混用单位。导入导出与二维码依权限提供。

详情：固定设备身份与关键状态，首屏概况和未闭环事项。分为概况、技术参数、结构与安装、点检保养、故障维修、BOM与备件、运行监测、生命周期、资产成本、资料与审计；移动端可折叠业务组，常用入口按角色排序。图片、模型、资料和履历仍在台账内，无独立菜单。

操作人员看当前状态、任务、二维码和异常上报；点检/维修人员看标准与作业对象；工程师维护结构、参数和策略；主管处理分配与变更；质量/安全/计量看适用证据及到期事项；财务看授权成本；审计看来源版本及不可覆盖历史。角色只是权限模板，还必须叠加组织、设备范围和字段密级。

## 分阶段落地与风险

第一阶段先完成逻辑设计：身份/分类/功能位置/参数模板/状态与主数据变更规则，以及装拆、更换、责任交接场景。同步更新角色场景、页面模型和候选记录，尚不编DDL。

第二阶段扩展台账列表/详情/维护表单及功能位置、模板等必要维护入口，再逐页补保养、BOM、故障停机、适用合规模型。关键设备合规随适用场景进入首期。

第三阶段补真实数采、财务成本、文件转换及3D；全部模型完成后统一正式数据库/API，保留旧调用方兼容边界。无后端数据量、接口性能与团队产能证据，不能给出可靠工期或宣称无迁移风险。

最大风险是历史身份映射、分类数据质量、装拆关系有效期、实时值来源和跨域授权，页面开发本身风险较低。主数据不能删除已引用设备；导入匹配不得只用可变名称/编码。

## 验收场景

设备移位保持身份与原位置快照；同位号换新设备保留两实体历史；电机跨泵装拆后履历跟随电机；模板升级不改变旧任务；人工值与陈旧数采明确标识；多工单同一停机区间不重复统计；无成本权限仍能看维护档案；某外部来源不可用不影响其他页签；关键检验到期阻断适用的使用许可；批量导入部分失败可定位并无静默覆盖。
