# 保养计划首批交付与验收记录

日期：2026-10-11。已实现两页：保养计划列表及保养计划详情，独立HTML；未改正式后端、数据库或现有调用方。

## 已实现

列表查询、弹窗高级筛选、统一表格/空态/load-status/分页、共享工具图标、列设置（刷新仍保持）、全授权范围JSON导出、刷新、新增。导入没有完整校验审批，明确禁用。主副标题分别单行截断，状态标签与版本分开。

详情保存草稿、项目增删、时间规则、岗位/人员多选、范围有效期、指定主责/主管派工、提交审核、独立批准/退回、暂停/恢复/终止、发布后修订。所有方法走maintenance-api异步request，配置、默认草稿和样本在maintenance-data JSON。设备配置由API投影现有台账会话，控制器不读取业务存储。

发布快照不可改写；修订草稿存在时仍使用旧发布快照预览，旧版可独立暂停/恢复，草稿不丢失。批准修订前不得改变设备ID；暂停状态批准新版本保持暂停，避免自动恢复调度。接口校验实际人员/角色映射及独立审批，不依赖按钮隐藏；成功记录完整字段前后快照。空创建请求不能从完整业务样本补足必填输入。

窗口预览按固定锚点和工厂日期计算，月末取当月最后一天，范围最多366天/100窗口；设备非在用或人员范围过期显示跳过理由。只读预览不创建任务，下一计划窗口采用JSON配置的示例日期2026-10-11，不声称真实自动调度。

档案保养→计划列表→详情保留设备/原页签/PC移动视图，来源入口返回原设备档案。档案现有保养记录仍是原归档投影，尚未聚合新计划及未来任务，本批不提升为完整保养业务闭环。

## 实施裁决与边界

- 沿用当前原型目录实施，保持本地服务路径，未迁移现有未提交资产或改无关配置；不创建Git提交。
- 岗位/人员共同有效期已实现，各绑定独立有效期及任务协作分工在任务批次；并未假称派工已完成。
- 导出为授权JSON，无Excel导出；列设置是当前页面偏好，刷新读取保持，跨页持久化另行设计。
- 当前合法EAM人员均可只读计划；正式租户/组织/设备级权限继续在正式接口阶段统一设计。
- 未实现实际任务生成、执行、验收、物料扣减、安全作业许可流、实时调度和档案同源任务聚合；不能以计划发布代替保养完成。
