# 统一列表标题栏组件与数据工具设计

日期：2026-10-10。以点检任务列表块头为模板，覆盖13个业务列表，包含设备台账。

## 组件封装

统一静态HTML插槽：data-component=list-toolbar、business-panel-title、list-panel-tools、list-search-group。统一交互实现：shared/list-toolbar.js；预定义JSON配置：mock/list-tools-data.js；数据操作：mock/list-tools-api.js。

页面仍为独立HTML，组件只负责标题栏、工具弹窗和事件，不生成整个业务页面。主业务按钮保留原ID、权限与业务方法。搜索及筛选组成Bootstrap input-group；所有控件32px，图标16px，同一套线性SVG，工具具备title与aria-label。

顺序：搜索/筛选、导入、导出、刷新、列设置、业务主操作。小屏在同一块头内自然换行。设备导航树不受影响。

## 操作边界

- 导出：JSON文件，读取当前模拟权限范围全部记录，不限当前分页、不沿用当前界面筛选。名称与提示明确范围；设备台账此前CSV按钮改为统一JSON导出。
- 刷新：先调用模拟读取接口，已有页面刷新函数继续使用；无刷新函数的页面重新加载。
- 列设置：弹窗勾选隐藏/恢复，首列和操作列固定保留；会话保存，动态渲染后继续应用。
- 导入：JSON，2MB、1–500条；校验schema、page、rows与id/code、重复标识；错误保留输入与逐行信息。预览前三条，填写原因后提交暂存批次。支持幂等键；只允许工程师/主管。
- 导入当前止于“待字段映射审核批次”，尚无批次审核入库、撤回、批次列表或Excel字段映射；不得把此阶段描述为已完成各业务对象导入入库。导入不直接触发任务或改变故障/工单状态。

## 候选表及字段（正式模型后续统一设计）

| 候选结构 | 字段 |
| --- | --- |
| 导入批次 | id、page/业务对象类型、status、idempotencyKey、reason、createdBy、at、总条数、来源文件名称/哈希（后续）、校验版本（后续） |
| 导入明细 | 批次ID、行号、来源JSON、对象标识id/code、字段映射版本（后续）、校验结果/错误、审核结果（后续）、正式实体ID（后续） |
| 用户列表列偏好 | 用户ID、页面标识、列标识、显示顺序/可见性；当前原型仅会话内列索引 |

批次保存在会话独立键eam-import-batches；不写业务实体表。原型索引型列偏好不能直接作为正式列模型。

## 候选接口

| 方法与路径 | 输入/结果 |
| --- | --- |
| GET /list-tools/export | page；返回schema、page、scope、rows |
| POST /list-tools/import/validate | page、data；返回rows、count、逐行errors |
| POST /list-tools/import | page、data、reason、idempotencyKey；返回批次id、count、status |

导入批次查询、字段映射、审核/撤回、正式入库接口尚待设计，本次未虚构实现。列偏好当前无服务接口，后续以用户偏好模块统一实现。
