# 导航布局与字体优化验收记录

日期：2026-10-10。依据：用户确认的菜单排序、图标、独立滚动、字体及操作列优化。

## 实现

1. 模块菜单按工作入口、设备资产、日常维护、异常处置、维修闭环、基础配置六组排列。15个业务菜单均使用同一线性SVG图标风格，修正分类模板的选中映射，增加aria-current。返回平台置于业务菜单末尾，原型范围移入演示设置。既有业务角色/动作授权保持原规则，此次未新增正式权限模型。
2. 固定应用外壳占满可用视口，文档不滚动；左侧菜单和主内容各自滚动。移动端顶部、底部导航固定，内容区留出底栏安全空间。打印时恢复完整文档流。
3. 字号：页面标题22px、区块标题16px、菜单/正文/表格14px、说明/编码12px、按钮/标签13px。移动输入16px，主要触控操作44px。
4. 操作列不换行，最多两个直接操作，其余保留原事件并收进更多。原有台账更多菜单继续沿用。更多浮层使用固定定位，按视口边界调整，支持点击外部、Esc及内容滚动关闭，避免被表格容器裁切。
5. 原生弹窗独立滚动、打开时锁定背景；关闭恢复打开前的业务滚动位置。移动抽屉同样锁定主内容。

## 实际验证

- 25个页面入口 × 1366×768/390×844，共50次布局约束检查：主内容overflow-y为auto、顶栏顶部为0、外壳高度匹配视口、无文档横向溢出。详情见导航布局与字体双端检查.json。
- PC异常列表主内容滚动377.6px，文档滚动0、顶栏顶部0、侧栏滚动0，证明业务区与外壳独立。
- 台账档案和编辑按钮顶部均为408.675px；更多菜单position=fixed，显示范围443.675至667.275px，未被表格截断。
- 移动编辑弹窗打开/关闭，主内容滚动均为274.8px；模块抽屉打开/关闭后仍为274.8px，文档滚动0。
- 82项Node模拟业务测试通过；公共脚本语法检查、样式工程检查、设计一致性检查通过。未提交业务单据。
- 截图：导航布局修复-PC.png、导航布局修复-移动端.png。

## 数据与接口影响

仅调整客户端导航结构、布局、字体和按钮呈现；无新增业务对象、候选字段或接口。各独立HTML仍通过原JSON模拟API获取业务数据，不生成整页。此次50次检查为基础布局证据，不代表所有角色与全部业务状态E2E通过。
