# 台账资料与点检责任设计

日期：2026-10-10。适用：首批高保真原型与后续商业产品设计。以下规则覆盖此前独立图片/履历菜单和单执行人计划设计。

## 导航与对象边界

系统平台 → 设备管理 → 设备台账 → 某台设备全景档案。图片/3D、技术资料、生命周期履历是该设备的页签；资料维护用设备内弹窗，上传时固定当前设备，不能无意换关联对象。设备资料与履历不设独立业务菜单。内部asset-files.html和history.html保留为可维护子操作文件与兼容深链接，不等于菜单；相关页面均计入逐页登记。

原E04/D01保留为台账能力编号而非菜单入口，现有能力未删除。全量菜单入口从57调整为55；原13项切片对应11个菜单加2项台账能力，仍有44菜单等待完整模型。操作审计D03是系统级审核能力，不能与单设备履历混淆。

## 设备图片、资料与履历

| 场景 | 行为与约束 |
| --- | --- |
| 多图新增 | 单批1至10个、合计150MB；图片10MB、文档25MB、模型100MB，正式限额按平台文件策略配置；按分类校验扩展名/大小；所有文件通过后整批保存，重复有效名称+版本拒绝；本机存储失败不写业务关联 |
| 图库 | 图片缩略图、数量、主图；点击放大，上一张/下一张及左右方向键循环；Esc/关闭返回原页面；示意图明确标记 |
| 主图 | 首张有效上传图片默认主图；可以切换，设备最多一个有效主图；移除主图后选择下一张；主图属于有效设备图片 |
| 文件预览 | PDF和文本可查看内容；Office显示待转换预览并提供授权下载；3D文件可关联，真实模型渲染尚未接入；内容缺失显示原因，不用元数据冒充内容 |
| 下载授权 | 查看、下载、维护是独立权限。演示操作人员/点检人员可查看但不能下载；工程师/主管、质量、安全、计量、审计、管理者可下载。正式权限引用平台授权+组织/设备范围+资料密级+版本状态 |
| 受控资料 | 原文件对象与设备关联分离，名称/版本/分类/大小/MIME/扫描状态/存储键/主图/关联状态/移除责任留痕；删除关联保留历史，不将历史内容冒充当前有效文件 |
| 履历 | 在设备内筛选事件类型和日期、查看来源版本与审计快照；发布版本跳转带revision并只读；删除草稿只看快照；按设备实体和关联ID过滤，其他设备事件不能串入 |

本机IndexedDB仅为原型内容存储，不是正式上传；业务元数据仍为模拟会话。异步保存校验会话版本及实际人员/角色，冲突不覆盖同期变更；临时内容用UUID隔离，失败回滚。下载按钮调用本机原文件下载并记录download_requested，不能把请求发起当成浏览器已收到文件；本轮自动捕获下载超时，未取得实际下载证据。

正式文件服务必须实现安全类型识别、病毒扫描、PDF/Office安全转换、预览状态、短时预览票据/下载票据和拒绝/许可审计；客户端按钮禁用不构成服务端鉴权。模型需检查GLB/glTF依赖、资源规模、版本及设备节点绑定。与全部页面记录汇总后统一正式数据库/API设计。

## 点检计划和任务责任

计划名称统一为点检计划。标准决定内容与判定，路线决定设备/部位顺序，计划决定频次、窗口、适用日历和责任候选范围；任务是具体业务日期/窗口的个人责任实例。

计划绑定支持指定人员、多岗位、岗位与人员组合，均允许多选。岗位引用平台组织/岗位/任职主数据，与权限角色分开；同一人多岗位命中或又被直接指定，只出现一次。计划保存/生成校验岗位存在与在岗人员、人员有效与点检资格。正式有效期、组织范围和排班来源由候选接口获取；当前仅模拟成员/资格，不宣称已接真实排班。

| 分配方式 | 生成规则 | 幂等规则 |
| --- | --- | --- |
| 候选池派工 | 主管从去重候选池指定一位主责任人；只有一个候选时可唯一确定；多个候选未选人则阻断，不生成无人负责任务 | 计划版本+设备+日期+项目组+窗口唯一；改选另一人不能再次生成，必须走改派 |
| 逐人执行 | 需要每位候选人分别执行时，为每人生成独立个人任务；不是多个人共用一个结果 | 以上维度再加人员ID；每人的结果、草稿和验收身份独立 |
| 待执行改派 | 仅工程师/主管，在任务冻结候选范围内指定合格人员，原因与版本必填；已执行不能换责任人；原草稿失效且快照保留 | 保留原生成键，增加任务修订及改派审计，拦截同人同窗项目重复 |

生成时冻结计划版本、标准、绑定来源、候选人员、选定执行人和分配策略。岗位任职变化不反写旧任务；正式系统生成预览/执行需要排班版本冲突检测。协作者与主责任人分表记录，不能给一条任务设置多个共享主责；当前协作业务UI尚未实施，候选字段已登记。计划草稿不影响生成，发布后新任务采用新版本，旧任务保留快照。
