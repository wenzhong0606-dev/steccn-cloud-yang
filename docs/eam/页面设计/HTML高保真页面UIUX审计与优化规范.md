# HTML 高保真页面 UI/UX 审计与优化规范

日期：2026-10-10。适用于现有首批20页和后续所有EAM高保真页面。设备管理是平台内二级模块；PC与移动端共享权限、对象和状态规则。此规范是内部产品设计门槛，不表示生产系统或认证验收已经完成。

## 1. 整体视觉规范

所有页面只引用shared/style.css；颜色从令牌.css取得，禁止页面硬编码颜色。主色、文字、背景、边框及成功/警告/危险色均使用语义变量；浅色、深色、跟随系统共用同一组组件。当前主色#245ad3，背景#f3f5f9，正文#1d2b40；具体数值以令牌文件为唯一来源。

间距采用4/8/16/24/32px；圆角6/10/14px；字体Segoe UI、Microsoft YaHei；字号12/13/14/18/26px。正文默认14px，次要文字不能依赖低对比颜色隐藏信息；金额、数量采用等宽数字。图标使用同一套线形风格，必须保留文字或可访问名称，不以emoji承担业务状态。阴影仅用于浮层和必要层级。

常规正文对比度内部验收目标4.5:1，大字及非文字控件3:1；每次新增主题重新检查，不以当前主题切换通过代替全量对比度审计。

## 2. 页面布局

层级为平台导航→模块导航→面包屑与页面标题→指标/核心状态→主要业务区→辅助信息。模块菜单默认216px，1200px以下184px，1024px以下抽屉；内容最大1680px，2000px以上1840px。主体使用minmax(0,1fr)，避免长内容撑开页面。

列表采用页头、查询区、结果及分页；详情采用对象身份、核心状态、业务标签页；执行页采用任务摘要、操作内容、提交区。指标默认四列、窄屏两列，业务分栏在窄屏纵向排列。禁止为每页另造页头、导航和卡片布局。

## 3. 组件样式统一

| 组件 | 统一规则 |
| --- | --- |
| Button | PC高40px，触屏44px；新增/提交为主按钮，编辑/导出次按钮，删除/停用危险按钮；页头放全局操作，行末放对象操作，表单尾部放取消和提交 |
| Input/Select/DatePicker | 标签常驻，必填及错误可见；当前日期控件采用浏览器原生日期选择器，弹出面板差异保留，不宣称自定义日期组件完成 |
| Table/Pagination | 标识左对齐、数值右对齐、状态Tag；表头、斑马纹、Hover统一；容器独立横向滚动，可冻结标识列；分页在结果底部 |
| Tabs/Card | 卡片标题与内容间距固定；Tabs提供selected及键盘左右/Home/End切换，面板关联aria-controls |
| Modal/Drawer | 标题、内容、底部操作分区；高度不超过视口，内部可滚动；模块抽屉有遮罩、关闭、Esc和焦点循环 |
| Tag/Badge/Tree | 颜色与业务语义一致；状态同时有文字；树层级缩进、选中、高亮统一 |
| Tooltip/Dropdown | 提示不能承载唯一必读信息；菜单关闭和键盘可达必须测试；当前Tooltip为公共样式能力，后续实际实例仍需验收 |

禁用必须说明原因；权限控制以正式后端为准，原型按钮不能代表鉴权已实现。

## 4. 数据展示优化

数字显示单位、精度和统计时间范围；0、缺失、未采集必须区分，缺失显示“—”及必要说明。日期统一YYYY-MM-DD，时间带业务时区；编号不能按数字格式化。长名称可换行，截断必须支持查看完整值。异常用局部状态标签，不整屏标红。

移动端默认将表格转为带data-label的记录卡；需要跨列比较的表格可显式标记data-mobile="scroll"。空数据区分无记录、无筛选结果和无权限；提供匹配的创建、清除筛选或返回入口。图表须包含单位、图例、时间范围、空态，模拟数据明确来源，不假装实时采集。

## 5. 交互状态优化

| 状态 | 验收要求 |
| --- | --- |
| 默认/Hover/Focus/Active | 状态一致，键盘焦点清晰可见，不只依靠鼠标 |
| Selected/Disabled | 选中有文字/结构反馈，禁用不可提交且原因可理解 |
| Loading | 操作带aria-busy，禁止重复提交；上传已接入忙碌态；真实网络超时后续集成验证 |
| Empty/Error | 区分业务原因，保留输入，提供可执行恢复动作 |
| Success/Warning | 成功反馈对应实际结果；危险动作二次确认，警告不与错误混淆 |

新增、编辑、删除、审批、上传、下载、撤回、改派需结合角色与状态逐项验证。公共CSS覆盖状态外观不等于所有业务状态均已实现。页面需跳到内容入口、可访问名称、语义表头和表单标签。对话框的焦点返回及表单错误关联须逐实例验收。

## 6. 响应式与不同分辨率适配

必测390×844、1366×768、1920×1080、2560×1440；并检查1093×614和911×512等效CSS视口，近似1366屏幕125%/150%缩放造成的可用空间。等效视口不替代真实Windows DPI、浏览器缩放、字体渲染验收。

页面根节点不得横向溢出，表格内部滚动允许；弹窗操作按钮必须可达，长列表和长文本不得遮挡底部导航。PC/移动切换只改变布局，不改变身份、状态和权限。侧栏收缩、卡片换行、文件预览、键盘抽屉、手机安全区均纳入检查。

## 7. 信息层级与业务可读性

设备详情优先呈现核心生命周期/运行/可用状态，再呈现基础信息及当前未闭环事项；点检/保养、维修、备件、生命周期、日志通过业务分区或标签页查看。当前运行数据必须附时间和来源；不支持采集时明确显示缺口。

图片、文档、3D模型和履历属于设备台账对象内部，不设独立业务菜单。多图缩略图、主图、放大轮播；文件内容预览与下载权限分离；3D示意和真实模型服务分开标识。工作台按角色组织待办、风险与快捷入口，不使用一套通用指标冒充所有角色。

## 8. 工程与代码层面的样式治理

shared/style.css为唯一入口；@layer顺序tokens→base→layout→components→business→responsive，对应令牌.css、基础.css、布局.css、组件.css、业务.css、响应式.css。业务选择器限定业务区域，禁止页面覆盖全局按钮、输入及表格。旧product.css仅保留兼容说明，不再引用。

禁止HTML内联style和页面style块；唯一!important例外为基础层[hidden]的隐藏保障。JS临时toast显隐及3D几何旋转可使用运行时属性，不能以此写视觉主题。公共ui.js仅负责主题、导航、键盘语义，业务内容保持独立HTML；不拼接整个页面。主题偏好属于界面偏好，不新增业务表/API。

多语言采用可换行、弹性宽度与语义布局；正式翻译资源和真实长译文回归尚未接入。减少动态效果并尊重prefers-reduced-motion。修改公共样式需回归全部已登记页面；样式工具保存在tools/eam，文档保存在docs/eam，临时文件用完删除。

## 发布门槛与记录

每页同步候选表、字段、关系及接口记录；不按页面机械建表，所有模型完成后统一设计正式数据库/API。每次审计记录页面、角色、数据场景、尺寸、主题、失败及修复证据。阻断项：业务按钮不可达、页面根溢出、重要数据隐藏、权限/状态混淆、提交无反馈、文档与模型矛盾。未验证项必须显式列出，不能以截图代替业务验收。

运行tools/eam/校验界面样式规范.py和校验设计一致性.py；公共交互变化补充浏览器检查，业务规则变化运行相应规则测试。静态检查、浏览器布局、业务测试及真实后端证据分别记录。

## Bootstrap 5 实施约束（2026-10-10）

统一入口shared/style.css固定加载本地Bootstrap 5.3.3，再按tokens/components/layout/pages分层。卡片、按钮等存在组件局部变量时，在相应组件映射Design Token，禁止只修改根变量并假定已生效。公共组件的原生button规则排除.btn；动态操作控件经公共UI装饰统一，统计卡和页签保留专属语义。响应式媒体查询与关键帧必须保留有效at-rule。

应用抽屉层级须高于sticky顶栏。移动预览须同时限制内容和底栏宽度；移动列表卡片不得继承桌面最小列宽。可折叠的设备树与概览默认在移动端收起，桌面展开。深色主题同时设置data-theme和data-bs-theme，并检查卡片、表格、表单、弹窗及按钮文字对比。

实施及证据见[Bootstrap样式修复验收记录](维护业务原型/Bootstrap样式修复验收记录.md)。


## 导航、滚动与操作密度（2026-10-10）

业务菜单按工作入口、设备资产、日常维护、异常处置、维修闭环、基础配置顺序分组，图标使用统一18px线性SVG，选中项明确标记aria-current。演示工具放入演示设置。菜单权限展示最终由正式平台授权决定，不用UI分组替代后端授权。

应用文档不滚动，侧栏和main各自滚动；顶栏固定在内容滚动区域之外。移动内容须预留底栏与安全区。弹窗打开锁定背景，关闭保留内容位置。字体统一22/16/14/12px层级，按钮与标签13px，移动输入16px。

列表操作最多两个直接动作，其余进入更多，操作列禁止换行；通过保留节点及其事件保持动作功能。更多浮层须越过滚动容器裁切限制，按视口定位，并提供外部点击/Esc/滚动关闭。验收记录见[导航布局与字体优化](维护业务原型/导航布局与字体优化验收记录.md)。


容器高度由应用外壳分配，flex/grid子项必须允许min-height:0；容器标题/工具栏/页脚不进入滚动区域，中部内容overflow:auto。台账表头在表格内部吸顶，避免主内容和表格重复纵向滚动。移动端保留分页与主要操作的可见空间。设备档案摘要须紧凑，避免挤压内部面板。


全页面以设备台账Bootstrap表格为基准：静态及异步动态行同样治理，主副标题各占一行且各自截断；编辑控件不参与截断；状态徽标不得套文本块截断规则。列表固定首尾、内部表格滚动，表单保留字段分区。统一实施见[全页面验收记录](维护业务原型/全页面样式统一验收记录.md)。
