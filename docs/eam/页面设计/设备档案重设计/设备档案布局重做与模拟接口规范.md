# 设备档案布局重做与模拟接口规范

日期：2026-10-10。替代上一轮“空白说明加历史样本”的展示方法；原PRD业务范围继续有效。

## 页面与交互

页面仍为独立 `device.html`，从平台设备管理模块进入。紧凑页头与72像素设备图组成身份摘要，五个状态使用同一接口响应；生命周期使用独立状态字典，禁止将任务“执行中”用于设备“在用”。PC以档案分组侧导航直接访问21个视图，导航独立滚动；手机以横向导航访问，表格内部滚动。

概况展示异常、维护及资料指标、基础字段、组织位置与采购记录；状态展示五维状态、来源时间、实际使用限制及生命周期操作。参数、BOM、位置安装、保养、故障、维修、测点、读数、成本使用专属业务列；更换页把实例寿命指标与更换履历分开，使用量=当前累计−安装基准，剩余量=目标−使用量。金额右对齐并保留两位小数，数据质量与处置状态使用标签。

列表支持关键词检索、每页8条分页、无匹配/无记录、读取中、读取失败及重试；快速切换视图丢弃旧请求响应。详情展示记录编号、设备、业务内容、依据、来源、版本和时间。真实会话单据允许打开来源；历史预定义记录不跳转至不存在的单据。参数编辑具备原因、权限、版本比较、保存及审计；生命周期与专业放行由既有领域规则校验。资料继续支持本机上传、缩略图轮播、内容查看及权限下载；3D仍为概念示意，尚无真实模型渲染器。

## 统一模拟接口规则

此规则用于后续所有页面设计：凡正式产品需要通过接口读取的业务数据，先在独立JS中定义可序列化JSON对象，再通过异步模拟接口读取；HTML只保存结构、控件及静态提示，不保存业务记录。页面控制器不得直接引用模拟数据对象。新增页面必须同步登记数据对象、可能表/字段、接口及异常状态。

本轮设备档案：`mock/archive-data.js`保存原始样本，`mock/archive-api.js`定义 `EAM_ARCHIVE_JSON` 资源及 `EamArchiveApi.request`，`scripts/archive-page.js`消费响应。文件元数据由同一模拟接口读取，本机Blob内容继续走IndexedDB。既有会话模型由模拟服务层投影为JSON响应，供页面调用；数据返回深拷贝，避免页面改动响应污染数据源。参数修改保存在独立会话键 `eam-archive-json-v2`，不重置原有用户记录。

模拟调用形式：`await EamArchiveApi.request('GET', '/equipment/EQ-001/archive')`，返回 `{code:200,data:{...}}`；使用Promise模拟延迟，并非真实HTTP服务。演示场景可返回空列表、持续读取中、权限拒绝、服务失败和版本冲突。当前迁移范围为设备档案；其他既有页面的会话直读尚需后续迁移，不能宣称22页已全部完成此规则。

| 本机模拟路由 | 请求 | 响应 / 校验 |
| --- | --- | --- |
| GET /equipment | 授权设备范围 | items设备列表，供资料设备选择 |
| GET /equipment/{id}/archive | 设备ID | equipment、states、fieldLabels、维护/异常/资料指标、权限及files |
| GET /equipment/{id}/domains/{domain} | 设备ID、领域 | items、total、columns、asOf；更换领域另有lifetime |
| GET /equipment/{id}/domains/media | 设备ID | 示例及本机文件关联元数据 |
| GET /equipment/{id}/domains/restrictions | 设备ID | 实际专业限制记录 |
| PATCH /equipment/{id}/domains/parameters | id、revision、content、reason | 新版本参数；拒绝越权、报废设备、旧版本及缺失必填 |
| POST /equipment/{id}/domains/lifecycle | next、reason | 生命周期及现有未闭环业务校验 |
| POST /equipment/{id}/domains/restrictions | id、opinion | 专业资格和独立放行依据校验 |

这些路径是原型适配层路由，不新增正式服务契约；正式候选API仍依据已有107项登记统一收敛。

## 数据结构记录

沿用[候选数据关系与接口边界](设备档案候选数据关系与接口边界.md)与[逐页记录](../页面记录/设备全景档案-页面数据与接口记录.md)。本轮明确展示DTO字段，不按页面新建实体表。

| 领域 | 候选数据字段与关系 |
| --- | --- |
| 设备摘要 | equipment_id、code、name、model、owner_person_id、serial_no、classification_id、asset_code；组织/位置/功能位置投影 |
| 状态 | equipment_id、dimension、value、source、observed_at、received_at；限制独立关联设备与专业处置 |
| 参数 | parameter_value_id、equipment_id、template_revision、parameter_definition_id、value、unit、value_type、revision；审计前后值与变更原因 |
| 更换与寿命 | replacement_id、part_instance_id、old/new_instance_id、installed_at、order_id、acceptance_id、baseline_counter；策略target、counter当前值、unit、as_of |
| BOM与测点 | material_id、bom_revision、quantity、unit、part_id；point_id、equipment_id、part_instance_id、reading、unit、quality、observed_at |
| 维护与故障 | plan_id、岗位/人员关联、frequency、due_at；任务唯一主责、完成记录；failure_id、downtime、repair_order_id、executor_id、status |
| 成本 | financial_asset_id、cost_entry_id、amount、currency、accounting_date、voucher_id；来源凭证与设备/工单关联 |
| 履历与审计 | event_id、equipment_id、source_type/id、actor_id、event_at、before/after、reason、revision；不是页面独立表 |

列表响应的columns为原型展示元数据，正式产品DTO不一定沿用。此阶段不产出DDL或正式OpenAPI。

## 验证与剩余范围

51条本地规则/模拟接口测试通过，包括返回值隔离、设备隔离、生命周期翻译、参数版本与审计、成本权限、失败不写入及寿命关系。浏览器核对21视图在1366×768和390×844共42个状态：每次仅一个业务视图，无整页横向溢出；浏览器实际完成参数保存与审计查询。

浏览器还验证接口失败提示和空列表，结束时恢复正常场景及设备工程师身份。参数保存验收保持75 kW业务值，并留下一条核对记录。JS语法校验、样式门禁、PRD映射及文档链接一致性检查通过；22页记录和107候选接口索引已重新生成。旧设备档案控制器、分组脚本和追加样本渲染器已移除，不再并行加载两套逻辑。

本轮完成布局与聚合交互，不等同全PRD CRUD完成。完整保养执行、BOM版本维护、安装更换事务、参数审批、全域完整性规则及正式后端鉴权仍需专业页面批次。正式数据库和接口在全量页面模型完成后统一设计。
