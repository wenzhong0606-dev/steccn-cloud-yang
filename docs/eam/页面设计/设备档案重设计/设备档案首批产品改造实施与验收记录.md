# 设备档案首批产品改造实施与验收记录

日期：2026-10-12。依据：[逐页签产品审查报告](设备档案逐页签产品审查报告.md)。范围：现有 HTML 模拟原型第一批业务理解改造；新组件使用仓库本地 Bootstrap 样式。

## 已实施

| 审查问题 | 本批行为 | 验收依据 |
| --- | --- | --- |
| 概况统计与入口不一致 | 未结指标明确为业务对象数，进入关联业务的未结视图；已分诊异常不计入；同链对象不声称是独立问题数 | 默认样例指标 11，清单共 11 条 |
| 保养统计混淆策略与任务 | 指标改为保养任务，进入任务视图；计划、任务、执行履历独立切换 | 默认样例任务 0、计划 3；生成任务后按任务对象计数 |
| 文档数量包括图片与模型 | 技术文档指标与清单均仅统计当前设备的有效 document 资源；所有示例文档进入清单 | DOM 验收核对指标与文档条数 |
| 点检对象混排 | 待执行任务、历史记录、适用策略切换；完成状态 complete 不留在待执行视图；结果详情显示测量和证据 | 实际页面脚本回归完成任务隔离 |
| 缺陷混入故障且展示停机列 | 页签明确为缺陷与故障，按类型切换；缺陷不展示停机列；故障保留功能影响与恢复时间，停机小时由发生至恢复区间计算 | FL-1002 区间 11:00 至 11:45，展示 0.75 h |
| 专业详情丢失责任、验证与后续依据 | 复用详情容器，Bootstrap Card 分区呈现对象责任、执行验收、终止后续；读取 verification、review、authorityReceipt 与逐问题承接安排 | 真实模拟 API 验证与独立代码复核 |
| 保养历史证据混用当前版本 | 提交、验收、终止履历绑定对应原始对象与执行版本，V1 退回及 V2 提交后保留 V1 原证据 | 实际生成、开工、提交、退回、恢复、再提交回归 |
| 状态及限制来源不清晰 | Bootstrap 响应式五类状态矩阵，展示来源、业务/采集时间与范围；限制展示责任、期限、解除条件及来源入口；失效信号显示未知 | 浏览器状态矩阵截图；限制继续由来源专业流程放行 |
| 来源入口层级过多 | 有来源的对象名称直接打开正确来源；保留设备与返回页签；详情仍提供只读查看 | 档案导航上下文测试与真实页面脚本回归 |

来源未提供的专业字段显示“来源未提供”；历史样本明确标识，不作为当前流程闭环证据。保养接口读取时间与来源最新业务时间分别显示；混合清单来源不再取首条记录代表全表。

## 组件与接口

- 新增 `prototype/shared/archive-domain-ui.js`：Bootstrap 分段按钮、领域列配置、对象分类过滤、专业详情 Card。使用 `aria-pressed` 表达当前选择；用户操作可通过原生按钮键盘完成。
- 页面继续复用共享清单、筛选、分页、加载状态和详情容器，保留来源业务的权限与写操作边界。
- 原接口路径不变：设备档案摘要、领域读取、问题来源及保养来源接口；投影增加对象类型、未结标识、责任展示和结构化只读详情。
- 页面引入已修改脚本的新版本号，避免浏览器缓存旧控制器导致新骨架与旧交互混用。

3. `npm test --prefix tools/eam/组件测试`：组件契约、迁移及页面初始化套件全部通过，其中页面初始化 30 通过、0 失败。最终结果见[组件页面回归结果](../../验收证据/设备档案首批产品改造/组件页面回归结果.txt)。
