# EAM 设备台账 — 设备档案页面完整功能与交互设计清单 V1.0

产品需求规格（PRD）｜适用于工业 EAM 设备资产管理系统｜覆盖碳捕集、余热发电及通用工业设备

本方案将“设备档案”定义为设备台账下的核心功能，包含设备档案列表、档案创建/编辑、设备全景详情、业务关联页面、操作弹窗及完整交互规则。

设计目标：一台设备，一个完整档案，一个统一入口，贯穿设备全生命周期。

与一般设备台账不同，设备档案不仅要解决“这是什么设备”，还要回答：

- 设备属于哪里、由谁负责、具有什么技术能力？
- 它的上级、下级、装配部件和备件是什么？
- 现在是否在运行、是否存在故障、是否需要维护？
- 最近做过哪些点检、保养、维修和备件更换？
- 什么时候需要再次维护，是否存在寿命或合规风险？
- 历史上发生过哪些改造、移动、替换和状态变更？

# 一、完整页面体系

建议设备档案划分为 5 个页面组、25 个主要页面或功能视图。

这里的“页面”既包含独立路由，也包含详情 Tab、全屏子页面及管理界面，并不意味着需要开发 25 个完全独立的前端组件。

## 1.2 信息架构


页面归属原则： 点检、保养、维修、BOM 等模块仍然拥有自己的业务数据。设备档案仅提供该设备范围内的聚合视图、快捷入口及经过授权的业务操作，不重新建立第二套业务数据。

## 2.5 左侧设备树

建议提供两个切换模式：

- 设备层级树：按照父设备、子设备组织。
- 功能位置树：按照厂区、装置、区域和安装点组织。

节点显示：名称、编号、子节点数量、异常提示（如适用）。

交互清单：

- 展开/折叠节点。
- 输入关键词定位节点。
- 点击节点筛选右侧列表。
- 右键或操作菜单查看详情、添加子设备（需权限）。
- 支持定位当前设备的父级和子级。
- 切换树类型不改变设备实际父子关系。
- 设备数量较大时按需加载节点。
- 防止循环父子关系。
- 对设备移动或拆装使用专门的业务操作，不通过普通拖拽直接覆盖结构。

### 交互细则

- 默认采用只读的信息展示模式，点击“编辑”切换到表单。
- 字段按组编辑，防止修改一个字段需要提交整页全部数据。
- 分类变化时重新匹配参数模板，显示迁移影响并保留必要历史。
- 修改设备编号时校验唯一性，并保留原编号历史。
- 修改制造商、型号等关键身份信息时提示对 BOM、备件匹配及技术参数的影响。
- 设备编码、Tag 位号、出厂序列号采用不同的唯一性规则，不能混用。
- 设备采购日期、验收日期、投运日期应进行合理的时间逻辑检查；允许记录经确认的历史异常数据并说明原因。

## D02｜设备技术参数区

### 内容分区

| 子区域    | 内容                 | 交互      |
| ------ | ------------------ | ------- |

| 基础技术参数 | 功率、压力、流量、容量、尺寸、转速等 | 动态字段展示  |

| 额定参数   | 额定功率、额定转速、额定流量等    | 查看参数值   |

| 技术资料   | 参数来源文件、技术规范书       | 打开关联文档  |

### 必须支持的交互

1. 根据设备分类或型号自动匹配技术参数模板。
2. 按参数组展开、折叠。
3. 根据参数名称快速检索。
4. 自动显示单位和数据类型。
5. 输入时进行必填、精度、范围及枚举校验。
6. 支持参数的批量录入与导入。
7. 修改关键参数时保留变更前后值。
8. 可比较两个历史参数版本。
9. 区分设备参数与运行采集值。
10. 模板升级时进行字段迁移及兼容性检查。

特别要求： 不应将实时温度、压力等采集值直接写入设备参数表，设计参数与实时运行数据应分别管理。

## D03｜设备结构与层级区

这是你之前讨论的大设备、小设备与备件关系的核心区域。

### 三种结构必须区分

| 结构     | 示例                 | 业务意义       |
| ------ | ------------------ | ---------- |
| 设备层级   | 汽轮发电机组 → 汽轮机 → 油泵  | 可维护设备的父子关系 |
| 功能位置   | 余热发电 → 汽机房 → 油泵安装位 | 工艺/空间安装位置  |
| 设备 BOM | 油泵 → 机械密封、轴承、叶轮    | 组成物料及可维护部件 |

### 页面应包含

- 当前设备及上下级设备树。
- 所属根设备。
- 上级设备及下级设备列表。
- 层级深度及结构路径。
- 当前设备是否独立维护。
- 子设备类型、编码、名称、状态。
- 子设备数量、异常设备数量。
- 当前结构生效时间。
- 历史拆装及层级变更记录。

### 交互

- 点击节点切换对应设备档案。
- 点击“添加子设备”进入选择现有设备或新建设备流程。
- 点击“调整层级”打开结构调整向导。
- 层级调整前展示受影响设备和关联数据。
- 检查循环引用、重复挂载、跨组织约束。
- 可查看某个历史时间点的设备结构。
- 可从子设备返回上级设备档案。
- 关键设备结构调整应支持审批。

不能因为某备件安装在设备上，就自动把它转换成设备树节点。是否建立独立设备档案应由维护和追溯需求决定。

| 组织位置   | 公司、厂区、车间、区域            |

- “安装设备”：选择有效安装位置，校验位置适用性。

## D05｜设备状态与健康区

### 状态分区

| 状态类型 | 展示内容           | 操作       |
| ---- | -------------- | -------- |
| 生命周期 | 状态、开始时间、当前阶段   | 受控状态转换   |
| 运行状态 | 运行、停止、待机、未知等   | 查看数据来源   |
| 健康状态 | 正常、关注、预警、严重、未知 | 查看判定详情   |
| 故障情况 | 未关闭故障数、故障等级    | 进入故障事件   |
| 管理状态 | 盘点、冻结等管理标记     | 根据业务权限维护 |
| 状态历史 | 状态前后值、原因、时间、来源 | 时间轴、筛选   |

### 关键交互规则

- 点击生命周期状态，展示允许的下一状态及前置条件。
- 点击运行状态，展示采集源或人工确认记录。
- 点击健康状态，展示报警、趋势、规则及更新时间。
- 状态未知不能默认为正常。
- 运行状态采集超时后显示数据过期或未知。
- 有未关闭故障不应自动让生命周期变为“停用”或“报废”。
- 状态变更应保留操作人、原因和关联单据。

## D08｜故障与缺陷档案区

| 分区   | 字段                   |
| ---- | -------------------- |

| 故障来源 | 点检、监测报警、巡检、人工报告      |

## D11｜备件更换与寿命区

这是设备生命周期中必须补齐的重要区域。

### 页面内容

| 子区域    | 字段与信息                  |
| ------ | ---------------------- |
| 当前装机备件 | 备件名称、物料编号、安装位置、序列号（如有） |
| 装机信息   | 安装日期、安装人、对应工单          |
| 寿命信息   | 寿命策略、设计寿命、额定运行次数/小时    |
| 使用情况   | 已用运行量、剩余寿命、数据来源        |
| 更换历史   | 原备件、新备件、拆卸/安装时间        |

| 拆下件处理  | 报废、维修、返库、待检            |

| 风险信息   | 到期、超限、异常磨损、缺少寿命依据      |

### 交互清单

1. 查看设备当前安装的备件及装机位置。
2. 从 BOM 选择物料并匹配适用性。
3. 选择具体库存件或序列化部件。
4. 发起拆卸/更换操作。

6. 记录旧件去向和新件安装信息。
7. 按策略更新寿命起算点。
8. 设备运行小时数变化时更新相关寿命指标。

10. 对检查后继续使用的备件发起延期审批。
11. 审批通过后记录新的复核日期/阈值。
12. 审批拒绝后保留原约束。
13. 完整保留旧件、新件及审批历史。

### 更换流程


不允许仅通过修改 BOM 中的物料编码，就认为现场完成了备件更换。

| 其他资料 | 技术变更、供应商资料 |

交互应支持上传、预览、下载、文档分类、关联业务事件、版本管理和权限控制。

### B. 生命周期时间轴

建议整合：

- 采购与到货。
- 安装与验收。
- 初次投运。
- 设备移位。
- 设备层级变化。
- 重大故障。
- 重大维修。
- 关键备件更换。
- 设备技术改造。
- 封存与重新启用。
- 设备退役及报废。

时间轴支持按事件类型、时间、来源模块筛选。点击事件打开原始业务单据，事件展示记录执行时的历史信息，而不是用当前设备参数覆盖历史。

### C. 字段变更与审计

| 字段   | 内容             |
| ---- | -------------- |
| 操作时间 | 精确时间           |
| 操作人  | 用户与来源系统        |
| 操作类型 | 创建、修改、关联、解除等   |
| 业务对象 | 设备、参数、位置、BOM 等 |
| 变更字段 | 字段名称           |
| 原值   | 变更前内容          |
| 新值   | 变更后内容          |
| 变更原因 | 说明或审批原因        |
| 关联单据 | 审批单、工单、变更单     |
| 操作结果 | 成功、失败及原因       |
| 追踪编号 | 请求或审计关联 ID     |

敏感数据的审计展示需要脱敏，不应在日志中泄露口令、Token 等秘密信息。

# 五、新建设备档案页面（A02）

建议使用 分步骤建档向导，而不是一张非常长的录入表单。

## 5.1 建档步骤

1. 身份与分类

   设备编码、名称、分类、类型、型号、是否独立维护
2. 组织与安装位置

   所属组织、部门、负责人、功能位置、上级设备
3. 技术参数

   自动加载参数模板、填写关键参数及设备级特殊参数
4. 制造采购及投运

   制造商、出厂信息、采购来源、验收和投运信息
5. 维护与关联配置

   按需关联点检标准、保养策略、BOM 和测点
6. 确认并保存

   检查必填项、唯一性、关系有效性、重复设备及档案完整度

## 5.2 建档页面交互

| 操作     | 交互要求                 |
| ------ | -------------------- |
| 下一步    | 校验当前步骤，再进入下一步        |
| 上一步    | 保留已经填写的内容            |
| 保存草稿   | 保存未完成的建档草稿，不生成有效在役设备 |
| 取消     | 存在未保存内容时二次确认         |
| 自动生成编码 | 按既有编码规则生成            |
| 设备分类选择 | 自动加载对应技术参数模板         |
| 上级设备选择 | 校验父子层级和组织规则          |
| 功能位置选择 | 校验位置状态及适用性           |
| 重复检查   | 按编码、出厂编号、位号等规则检查     |
| 保存     | 服务端再次校验并提交           |
| 保存成功   | 返回详情页，显示创建成功信息       |
| 保存失败   | 保留表单内容，定位失败字段        |

### 必须考虑的场景

- 设备尚未安装：允许建档但没有安装位置。
- 设备已采购但未投运：不能强制填写投运日期。
- 历史设备补录：允许输入历史日期并保留补录来源。
- 关键资料暂缺：允许符合规则的草稿或待完善状态。
- 设备编码冲突：禁止产生两个相同业务范围内的有效编号。
- 用户中途关闭页面：提示未保存数据。

# 六、编辑设备档案页面（A03）

编辑页面应尽量复用新建设备档案表单组件，但必须区分普通字段修改与需要专门业务流程的操作。

## 6.1 字段编辑策略

| 修改内容    | 建议方式           |
| ------- | -------------- |
| 设备名称、备注 | 普通编辑           |
| 制造商、型号  | 关键字段编辑，检查影响    |
| 技术参数    | 参数修改，记录变更历史    |
| 设备分类    | 受控修改，分析模板影响    |
| 设备负责人   | 责任关系调整         |
| 父设备     | 使用结构调整流程       |
| 功能位置    | 使用拆装/移位流程      |
| 生命周期状态  | 使用状态转换流程       |
| 设备 BOM  | 使用 BOM 版本变更    |
| 已安装备件   | 使用备件拆装/更换流程    |
| 运行状态    | 由状态来源或授权确认流程维护 |
| 累计运行量   | 使用计量器读数更正流程    |
| 财务净值    | 通过权威资产系统调整     |

不应该通过一个“编辑设备”按钮修改所有字段。

## 6.2 通用保存逻辑


对于并发修改，建议采用版本号或乐观锁保护，避免甲用户保存时覆盖乙用户刚刚更新的设备参数。

所有具有提交动作的弹窗都应该支持字段校验、权限校验、加载状态、重复提交保护、业务错误提示与成功反馈。

对于包含多字段、附件或审批流程的复杂操作，优先使用较宽抽屉或独立页面；对于确认操作，使用小型弹窗；对于简单数据选择，使用选择器或下拉面板。

# 八、重点业务交互场景清单

除了单个按钮，还需要设计跨区域、跨模块的完整业务联动。

| 场景        | 用户起点   | 必须完成的交互闭环                 |
| --------- | ------ | ------------------------- |
| 1. 查看设备   | 台账列表   | 列表 → 档案详情 → 对应栏目          |
| 2. 定位子设备  | 设备结构树  | 父设备 → 子设备 → 子设备档案         |
| 3. 设备移位   | 位置栏目   | 选择新位置 → 校验 → 提交 → 历史记录    |
| 4. 点检异常   | 点检档案   | 查看异常 → 关联缺陷 → 维修处理 → 闭环   |
| 5. 保养到期   | 保养档案   | 到期提醒 → 创建任务 → 执行 → 记录更新   |
| 6. 设备故障   | 状态/故障区 | 报告故障 → 创建工单 → 处理 → 验收     |
| 7. 备件更换   | BOM/维修 | 选择装机件 → 领用/更换 → 寿命更新 → 履历 |
| 8. 寿命延期   | 备件寿命区  | 复检 → 申请 → 审批 → 更新约束       |
| 9. 参数变化   | 技术参数   | 编辑 → 校验 → 版本变化 → 关联影响提示   |
| 10. 设备改造  | 设备操作区  | 改造申请 → 技术变更 → 验收 → 档案更新   |
| 11. 设备报废  | 更多操作   | 条件检查 → 申请 → 审批 → 关联对象处理   |
| 12. 查看历史  | 生命周期   | 事件筛选 → 事件详情 → 原始业务单据      |
| 13. 状态异常  | 设备摘要   | 异常提示 → 数据/故障来源 → 处理入口     |
| 14. 设备换装  | 结构/位置  | 原设备拆卸 → 新设备安装 → 历史保留      |
| 15. 档案不完整 | 列表/详情  | 缺失项 → 定位字段 → 补录 → 重新校验    |

## 8.1 特别重要：设备更换与设备位号的关系

例如原有 P-101 水泵拆除，安装另一台新泵。

在系统中，可能出现：

- 工艺位号仍然是 P-101。
- 功能位置没有变化。
- 物理设备 ID 发生变化。
- 新旧设备分别有自己的完整履历。
- 历史工单仍归属旧设备。
- 新设备开始自己的运行、维护和寿命记录。

因此建议档案中能够明确区分“当前占用该安装位的设备”和“历史上曾安装在该位置的设备”。

## 8.2 特别重要：备件更换对维护周期的影响

不能简单地认定每次更换备件都要重置整台设备的保养周期。

应根据维护策略判断：

| 场景      | 推荐处理          |
| ------- | ------------- |
| 更换轴承    | 重算或重置对应轴承寿命策略 |
| 更换机械密封  | 更新密封件寿命和更换记录  |
| 更换整台电机  | 新电机维护周期按规则建立  |
| 更换普通紧固件 | 不自动重置整机保养周期   |
| 整机大修    | 按大修策略调整对应维护基准 |
| 寿命延期    | 通过授权复检和审批更新约束 |

涉及多个维护策略时，应展示“本次更换会影响哪些周期”，确认后再更新。

# 十、全页面通用交互规范

以下清单适用于设备档案的所有页面。

## 10.1 数据展示规范

- 每个字段具有明确名称、类型、单位和业务含义。
- 日期和时间采用统一格式。
- 数值的精度和单位一致。
- 超长文本提供完整查看能力。
- 必填缺失、非适用、未知三种状态明确区分。
- 区分“暂无数据”和“数据加载失败”。
- 状态采用文字与图标共同表达，不仅依赖颜色。
- 实时数据展示采集时间和质量状态。
- 历史版本不被当前值覆盖。
- 外部系统数据明确标记来源。

## 10.2 表单规范

- 统一必填标识。
- 输入类型与业务字段匹配。
- 数值有上下限及精度校验。
- 日期有时间逻辑检查。
- 关联字段使用统一选择器。
- 支持字段级错误提示。
- 保存失败保留输入。
- 存在未保存内容时提醒。
- 重要操作提供变更影响预览。
- 关键业务变更保留原因与审计。

## 10.3 表格规范

- 支持分页、排序和筛选。
- 重要字段支持搜索。
- 可配置可见列。
- 列配置记忆用户偏好。
- 支持空结果重置筛选。
- 行操作菜单根据权限显示。
- 批量操作先检查所选数据适用性。
- 点击记录能进入关联详情。
- 数据刷新后保持必要上下文。
- 大数据量采用服务端分页或虚拟化等适用机制。

## 10.4 状态与反馈规范

- 初始化加载有骨架屏或加载反馈。
- 请求失败有清晰原因及重试入口。
- 保存成功有明确反馈。
- 提交操作防重复点击。
- 过期的数据明确提示。
- 权限不足给出友好说明。
- 并发修改冲突有差异提示。
- 状态转换失败不在前端假装成功。
- 业务异常可关联追踪编号。
- 关键操作完成后相关栏目同步刷新。

## 10.5 导航与响应式规范

- 设备档案具有唯一可访问的详情路由。
- 从工单、点检、保养等业务页面可返回设备档案。
- 页面刷新后仍可恢复到当前设备和对应栏目。
- 返回列表时尽量保留筛选条件和分页。
- 桌面端采用摘要 + 分组导航 + 主内容布局。
- 窄屏下自动调整导航，不遮挡业务内容。
- 大表格在窄屏时采用横向滚动或紧凑视图。
- 弹窗在小屏幕上不会超出可视范围。
- 关键操作按钮具有明确的禁用原因。

# 十一、设备档案完整性规则

建议新增一个“档案完整性”能力，而不只是展示完成百分比。

## 11.1 完整性检查分类

| 检查类型    | 检查内容         | 异常处理   |
| ------- | ------------ | ------ |
| 身份完整性   | 编码、名称、分类、型号等 | 定位基础信息 |
| 层级完整性   | 父子关系合法、无循环   | 定位设备结构 |
| 位置完整性   | 安装设备的位置有效    | 定位位置页面 |
| 技术完整性   | 必填技术参数已填写    | 定位技术参数 |
| 责任完整性   | 归属部门、责任人有效   | 定位组织信息 |
| 维护完整性   | 适用点检和保养配置    | 定位维护模块 |
| BOM 完整性 | 应维护的关键备件已配置  | 定位 BOM |
| 数采完整性   | 必要测点或计量器已映射  | 定位测点   |
| 合规完整性   | 必要证书、检验和校准要求 | 定位安全合规 |
| 数据一致性   | 业务状态与关联关系有效  | 打开异常明细 |

完整性规则必须具有适用条件。例如尚未投运的设备，不能因为没有运行小时数就判定档案不完整；不需要独立点检的组件，也不应强制绑定点检标准。

## 11.2 完整性页面交互

点击“档案完整性”后显示：

- 总体完整率与关键问题数量。
- 按领域分组的检查结果。
- 必须修复、建议完善、非适用项目。
- 缺失字段和对应业务规则。
- “前往完善”跳转按钮。
- 最近检查时间及规则版本。
- 允许的“非适用”说明和审批/确认历史。

对于关键设备，可以将部分完整性要求作为投运、验收或发布前置检查，但应通过可配置业务规则实施。

# 十三、开发实施优先级

为了让 AI 能直接根据这份清单拆解开发计划，我建议分为五个实施批次。

| 批次 | 内容                     | 完成标准             |
| -- | ---------------------- | ---------------- |
| P1 | 设备列表、建档、编辑、基本信息、技术参数   | 能完整建档、查询和编辑，校验有效 |
| P2 | 设备树、功能位置、设备状态、生命周期履历   | 结构、位置及状态可追溯      |
| P3 | 点检、保养、故障、维修关联          | 能从设备档案进入完整维护闭环   |
| P4 | BOM、装机实例、备件更换、寿命       | 备件装机关系与更换履历可核对   |

这只是实施分组，不代表将 P5 的数据关系全部留到最后设计。核心对象标识、关联契约、历史快照和权限范围需要提前统一。
