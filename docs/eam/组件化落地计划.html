1. 组件加载与初始化层

目录结构

prototype/ ├─ components/ # 可复用 HTML 片段（只含结构，无整页 html/head/body，无内嵌业务脚本） │ ├─ page-header.html # 页头 + 面包屑外壳，business 标题经 data-fill 注入 │ ├─ list-panel.html # 列表容器 + 工具栏 + 表格区 + 分页区（region: head/body/footer） │ ├─ filter-bar.html # 搜索 + 高级筛选触发（region: body） │ ├─ pagination.html # 上/下一页 + 计数（region: body） │ └─ dialog-shell.html # <dialog aria-labelledby> + 标题(与 header 同级) + form 外壳（region: header/body/footer） ├─ shared/ # 加载器、行为增强、公共样式 ├─ pages/ # 独立业务页面（声明引用组件 + data-fill 业务内容） ├─ scripts/ # 页面业务绑定（改为 init(root)） └─ mock/ # JSON 数据与模拟接口

声明式引用（约定属性）

<div data-component-src="../components/list-panel.html"
     data-instance="maintenance-list"
     data-component-required="true">
  <!-- 业务内容用 template 注入，见 §2；data-component 等既有标记由原 host 保留 -->
  <template data-fill="body"> …列表业务结构… </template>
</div>

data-component-src 是本项目约定属性，浏览器不识别，由 shared/loader.js 处理。HTML <template> 仅承载片段、不提供外部文件自动引用，故用运行时 fetch 插入普通 DOM（非 Shadow DOM）。data-component-required="true" 标记该组件缺失会阻断对应业务初始化（见 §5）。loader 插入骨架时保留 host 既有 data-component 等标记（增强器依赖），仅追加加载来源与完成标记。

加载器 shared/loader.js API

Eam.loadComponents(root=document) → Promise<Result>  // 递归查找 data-component-src，fetch 片段，注入 root，标 data-component-loaded
Eam.loadComponent(el) → Promise<Instance>           // 单实例重加载（首加载与重试共用，见 §5）
Eam.fillRegions(root)                                // 将 host 内 [data-fill] 模板克隆进片段 [data-region]（§2，未知/重复区域报配置错）
Eam.prefixIds(root, prefix)                         // 多实例：给 id 加前缀，同步 label[for]/aria-*/href="#…"（§6）
Eam.bootstrap(root, pageInit) → Promise             // 唯一启动流程（幂等，§3）
Eam.registerInit(fn)                                // 注册组件/模块的 init(root)，由 bootstrap 按序调用
Eam.dispose(root)                                   // 移除/替换节点时清理：含 root 自身，清除 data-component-loaded/prefixed/configError 标记
Eam.Dialog.submitGuard(form, onSubmit)              // 弹窗提交守卫：同步 preventDefault + busy + 仅成功关闭（§7.4）

加载顺序契约（加载器与协调器职责唯一）

1 加载组件（fetch+插入）
→
2 填充区域 + 前缀隔离
→
3 增强组件（bootstrap 协调）
→
4 绑定页面事件
→
5 页面自定义（接口/渲染在 pageInit 内）
职责边界（必修②）：loader 只负责获取 / 填充 / 隔离 / 失败重试 / 启动协调，不在 loadComponent 内做增强；增强与业务绑定由 Eam.bootstrap 按序调用（ui.init → pageHeader → 各 registerInit → pageInit）。首次加载与重试走同一 loadComponent 流程，重试仅由页面监听 eam:component-retry 补做该实例增强/绑定，不重跑整页。
// shared/loader.js 内 bootstrap（已校正：调用 pageInit，不引用未定义符号；幂等）
let bootPromise = null;
async function bootstrap(root, pageInit){
  if (bootPromise) return bootPromise;            // 幂等：自动启动与显式调用并发只跑一次（防片段双重插入）
  const r = root || document;
  bootPromise = (async () => {
    const res = await loadComponents(r);       // 1 加载 + 2 fill + prefix 已在内部完成
    if (typeof ns.ui?.init === 'function') ns.ui.init(r);            // 3 增强
    if (typeof window.EamUiComponents?.pageHeader === 'function') window.EamUiComponents.pageHeader(r);
    for (const fn of inits) await fn(r, res);   // 3 增强 + 4 绑定（Card/Tabs/Dialog/pageInit）
    if (typeof pageInit === 'function') await pageInit(res); // 5 页面自定义（接口/渲染在 pageInit 内部完成）
    return res;
  })();
  return bootPromise;
}

多实例与节点隔离

  • 实例前缀：data-instance="x" 时，片段内所有 id 重写为 x-<原id>，并同步 label[for]、aria-labelledby、aria-controls、aria-describedby、aria-errormessage、href="#…"（Eam.prefixIds，见 §6）。
  • 根内查找：组件 API 与页面绑定一律接收 root，用 root.querySelector，不用全局 getElementById，避免跨实例命中。
  • 推荐 data-ref：组件内部需被 JS 定位的节点优先用 [data-ref="rows"] 等稳定属性，而非依赖 id；id 仅用于 label / ARIA 关联（§6）。

循环引用检测（按 DOM 祖先链，非全局栈）

  • ancestorSrcs(host) 收集 host 的 DOM 祖先链上所有 data-component-src；若自身 src 出现在祖先链中才是真循环（兄弟并发加载同一片段不算），中止并渲染错误。
  • 失败请求须 cache.delete(src)，否则重试仍返回同一次失败 Promise（已验证：缺失片段重试修正 src 后可成功）。

加载失败

  • Eam.loadComponents 捕获单实例 fetch 错误，在该节点渲染错误 + 重试按钮（调用 Eam.loadComponent(el) 重加载），不留空白容器（§5）。

重复初始化与清理

  • 增强器可重复调用：先查 root.dataset.enhanced 或专属标记，已增强则跳过事件绑定（避免重复监听）。
  • 移除实例（如 SPA 切页）或替换节点时调用 Eam.dispose(root)；普通关闭弹窗不调用（保留实例可再次打开）。dispose 清除 root 自身及其子孙的 data-component-loaded/prefixed/configError 标记（必修③ + 试点修复 2）。
渐进迁移（必修⑤）：页面引入 loader.js 才走 Eam.bootstrap + Eam.registerInit；未引入的页面保持原立即执行逻辑、不受污染。每页只启动一次（bootstrap 幂等）。已迁移页保留原有数据/规则/导航/接口依赖。访问方式：项目预览服务器 http://127.0.0.1:8765/；fetch 片段需 http 协议，不能 file:// 直接打开。

2. 业务内容装入组件（填充契约）

组件外壳（如 list-panel.html / dialog-shell.html）只含稳定结构；该组件的业务内容（列表业务区、表单字段、操作栏）由页面提供，通过 <template data-fill> 注入到外壳的 [data-region]。

区域映射

页面 data-fill组件 [data-region]用途
data-fill="head"[data-region="head"]表头 / 工具栏标题区（如 list-panel 的工具栏按钮组由页面注入）
data-fill="body"[data-region="body"]主内容：列表行容器 / 表单字段 / 弹窗正文（必填，若外壳有该区域）
data-fill="footer"[data-region="footer"]操作栏 / 页脚：提交 / 取消 / 计数（如 dialog-shell 的 actions）

移动还是克隆

  • 采用克隆注入：Eam.fillRegions 对每个 [data-fill] 模板取其 .content（<template> 内容本身不渲染）克隆进对应 [data-region]。
  • 模板保留在 host 节点（<template> 天然惰性），因此重试 / dispose 后重新 init 可再次填充，无需重新 fetch 片段。
  • 从作者视角即"内容只写一处、出现在组件内"——不主张多份副本，故业务内容不应既在模板又在页面正文重复出现。

填充规则与边界（应补⑥：不静默忽略错误）

  • 填充发生在 prefixIds 之前：模板内业务节点携带的 id 一并被实例前缀改写，保证多实例隔离（§6）。
  • 未知区域：页面 [data-fill="x"] 但外壳无 [data-region="x"] → reportConfigError（渲染配置错误提示），不静默跳过。
  • 重复区域：多个 [data-fill] 指向同一 [data-region] → reportConfigError（不静默覆盖）。
  • 可选区域：外壳声明了 [data-region] 但页面未提供对应 data-fill，且非必需 → 留空（可选区域须在外壳中显式声明为可选）。
  • 必需区域缺失：外壳声明 [data-required="true"] 但页面未提供 data-fill → reportConfigError，等同于加载失败处理（§5）。
  • 嵌套组件：fillRegions 只处理本实例自身的 [data-fill] 与片段 [data-region]；嵌套片段新生出的 host 由 loadComponents 递归加载，各自独立填充。
  • 业务表单字段留在页面模板，不抽成独立 HTML（遵循核心原则）；组件只提供表单外壳与统一行为。
<!-- 页面：list-panel 业务内容 -->
<div data-component-src="../components/list-panel.html" data-instance="mt" data-component-required="true">
  <template data-fill="head"><h2 class="business-panel-title">保养任务清单</h2></template>
  <template data-fill="body">
    <div class="table-wrapper"><table class="data-table">…<tbody data-ref="rows"></tbody></table></div>
  </template>
  <template data-fill="footer">
    <button class="btn btn-primary btn-sm" data-ref="create">从计划生成</button>
  </template>
</div>

4. EamList 接口修正（实测）

v3 误述：EamList(records,{columns,actions}) 已支持。实测 list.js 并非如此——它是全局固定 ID + 页面 DOM 表头的单体实现，实例状态为闭包局部变量，不隔离。

当前真实实现（shared/list.js）

  • 固定 ID：list-rows / list-search / list-status / list-mine / list-empty / list-count / list-prev / list-next / list-primary / list-reset / list-mine-label 全部 document.getElementById。

  • 行操作来自 record.actions（数据驱动），操作单元格为固定逻辑。

  • 注：equipment.js / problem-page.js 等未使用 EamList，走各自自定义 render——这是另一处一致性缺口（见 §12 备注）。

5. 加载成功 / 失败 / 重试契约

返回实例状态

// Eam.loadComponents 返回
{ ok:boolean,
  instances: Map<hostEl, { src, status:'loaded'|'failed', error?, required:bool }>,
  failed: hostEl[] }
  • 单实例成功：标 data-component-loaded；执行 fill（§2）+ prefixIds（§6）+ 该组件 enhance(root)。
  • 单实例失败：host 内渲染"加载失败 + 重试"；status='failed'；不执行该实例 enhance。

业务初始化门控

  • page init(root,res) 接收 res；若某 host 标 data-component-required="true" 且 status==='failed'，跳过该区域业务 init并记警告，但页面其余部分照常初始化。
  • 判定"必需"：列表页的 list-panel、含表单提交页的 dialog-shell 应为 required；纯装饰组件（如 page-header）失败不阻断。

重试只补该实例（首加载与重试同一流程）

// 失败 UI 的重试按钮：仅调用 loadComponent —— 与首次加载完全相同的流程（fetch缓存/填充/前缀隔离/标 loaded）
Eam.loadComponent(hostEl).then(inst => {
  if (inst.status === 'loaded')
    host_dispatch(hostEl, 'eam:component-retry', { host: hostEl }); // 页面监听该事件，仅补该实例的增强/业务绑定
});
// 不重跑整页 bootstrap，不重渲染其他实例（实测：缺失片段修正 src 后 status=loaded）

契约：失败可恢复、重试最小闭环、不污染其他实例；首加载与重试共用 loadComponent，职责单一（必修②）。

6. 嵌套加载与 ID 引用

防错

  • 循环引用：ancestorSrcs(host) 收集 host DOM 祖先链上的 data-component-src；若自身 src 在其中则中止报错。兄弟并发加载同一片段不算循环（已用 jsdom 实测：同页两 list-panel 并发加载 list-panel.html 互不误报）。
  • 重复请求：cache:Map<src,Promise>；相同 src 只 fetch 一次，多个实例共享同一片段文本（各自克隆进自身 root）；失败时 cache.delete(src) 使重试真正重新请求。
  • 重复前缀：仅当 !root.dataset.prefixed 时执行 prefixIds，置标记防二次前缀导致 x-x-id。

ID 引用同步

prefixIds 除改写 id 本身，还要同步以下属性中的引用（将 #id 改为 #{prefix}-id）：

  • label[for]、aria-labelledby、aria-controls（v3 已含）
  • aria-describedby、aria-errormessage、href="#…"（页面内锚点 / 错误关联）

查询约定

  • 推荐组件 API / 页面绑定用 root.querySelector('[data-ref="..."]') 定位节点，不依赖 id。
  • id 仅保留给 label[for] 与 ARIA 关联等可访问性用途；业务查询优先 data-ref。

  • 只读 readonly：收集（值可见且应回传，仅禁止编辑）。
  • 安全边界：版本/权限校验由接口负责，前端 collect 不据 hidden 值做权限判断（§9）。

14. 组件迁移完成条件（硬性判据）

一个组件完成迁移，必须同时满足以下 6 条；任一条不满足即视为未完成、不关闭该组件迁移：

  1. HTML 片段唯一来源：结构只存在于 components/*.html；页面仅声明 data-component-src + data-fill，无重复内联结构。
  2. 行为唯一入口：增强 / 绑定只经组件 API（Eam.Card.enhance 等），页面内无重复扫描或重复绑定逻辑。
  3. 多实例互不影响：前缀隔离 + root 内查找，同页多实例状态/ID/ARIA 互不串扰。
  4. 加载失败可恢复：错误 + 重试入口；重试只补该实例、不污染其他实例。
  5. 旧调用已移除或登记例外：接入矩阵记录旧调用→新调用；允许例外须显式登记并说明原因。
  6. 相关业务回归通过：§13 业务回归中该组件对应场景全绿。

15. 回滚保护（文件快照，非 stash pop）

v3 隐患：git stash pop 不会自动丢弃本批改动并恢复到批次前状态，可能合并或冲突；git restore 还原 Git 版本会丢批次前未提交改动。

修正：每批开始前对清单文件做保留相对路径的文件快照；记录本批新增文件；回退从快照恢复，清理快照与新增文件。

# 批次开始前：相对仓库根保存本批前状态（不碰其他文件）
mkdir -p .batch/<batch>
for f in <清单文件相对路径>; do
  mkdir -p .batch/<batch>/$(dirname "$f")
  [ -f "$f" ] && cp "$f" .batch/<batch>/"$f"   # 已存在→快照
done
# 记录本批将新增的文件（批次前不存在），写入 .batch/<batch>/NEW.txt
printf '%s\n' <新增文件相对路径> > .batch/<batch>/NEW.txt

# 回退：从快照恢复已存在文件；新增文件按 NEW.txt 删除
for f in $(find .batch/<batch> -type f ! -name NEW.txt); do
  orig=${f#.batch/<batch>/}; cp "$f" "$orig"; done
while read -r nf; do [ -f "$nf" ] && rm -f "$nf"; done < .batch/<batch>/NEW.txt

# 批次验收通过后清理快照
rm -rf .batch/<batch>
  • 禁止 git reset --hard / 全量 git stash / git checkout . / git stash pop。
  • 快照只含本批清单文件与新增文件清单，天然保护 memory、报告、其他未跟踪改动。
  • 快照目录 .batch/ 不纳入提交（加入 .gitignore 或仅本地）。
