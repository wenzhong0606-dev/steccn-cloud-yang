# 首批原型字段与命令映射

> CRUD补全更新：当前操作以[首批页面操作矩阵](../页面设计/2026-10-10-首批页面操作矩阵与交互验收.md)为准，字段关系见[维护数据补充](../数据设计/首批维护字段与数据关系补充.md)。此前记录保留阶段证据，附件仍为元数据，真实后端未接入。


日期：2026-10-10。补充现有核心逻辑模型和字段字典。页面与表不是一一对应关系：详情、工作台、履历属于多个对象的查询投影；流程记录必须独立持久化。

| 会话字段/命令 | 目标逻辑对象与关键字段 | 持久化要求 |
| --- | --- | --- |
| role/personId、people | 平台人员、角色授权、组织范围 | 实际人员身份与角色分开，禁止同一人员自验收；原型身份切换不用于生产 |
| lifecycle/operating/health | 设备状态与状态记录 | 生命周期、运行信号、健康判定独立；来源时间、接收时间、操作者、原因 |
| restrictions/releaseRestriction | 设备使用限制 | 来源报告ID、限制类型、设立/解除人员、时间、解除意见；来源关闭不自动解限 |
| reports/report/triageCheck/professional | 异常报告、分诊 | 编号、设备ID、来源结果ID、发生时间、等级、描述、证据、结论、状态、责任人 |
| checks/checkResult | 专项检查 | 原报告ID、检查编号、方法、执行人、结论、意见、证据、完成时间；历史不可被新任务覆盖 |
| tasks/taskInstances/drafts/results | 点检任务、草稿、结果与明细 | 实际指派人、窗口、项目快照、标准/计划版本、值/单位、异常描述、执行/接收时间；生成幂等键唯一 |
| standard/standardDraft | 标准与版本/项目 | 上下限、方法、发布状态、起草人、审核人、发布时间；旧版本不可覆盖任务快照 |
| plan/planDraft/generateTasks | 路线、计划版本、任务实例 | 设备/部位/标准绑定、频次、窗口、执行人、版本、批准人；按项目组生成 |
| orders/start/pause/resume/cancel | 维修工单 | 报告ID、实际指派人、范围、优先级、状态、暂停/取消原因、安全隔离确认 |
| executions/finish | 维修执行版本 | 工单ID、版本、实际执行人、诊断、修复、试运行、工时、材料引用、安全确认、完成时间 |
| acceptances/accept/reject | 验收记录 | 执行ID和版本、验收人、恢复/试运行/消缺确认、结论、意见、时间；退回保留原记录 |
| events | 审计事件 | 对象类型/ID、命令、人员、时间、前后快照、版本；物理设计需防篡改与并发约束 |
| attachments | 附件与对象关联 | 文件存储ID、对象类型/ID、名称、类型、大小、版本、上传者、时间；原型只有会话元数据，完整关联尚未实现 |

这些是逻辑映射，不是已建表DDL。后续统一确定主键、租户/组织隔离、类型长度、索引、审计、删除策略、附件服务、事务及API契约。当前 domain.js 的数组用于原型验证，不能直接替代生产数据库模型。
